# 시연 시나리오 (demo 브랜치)

배포 주소에서 한 흐름으로 보여주는 순서다. 메시지 하나마다 LLM을 한 번 부르고, 기록 확인 문장은 코드의 고정 문장이다.

## 시연 전 준비

- [ ] Vercel에 `OPENAI_API_KEY`, `OPENAI_MODEL_PARSE`가 `demo`가 배포되는 환경에 들어 있다.
- [ ] 새 시크릿 창으로 연다. 기록·대화·이름은 브라우저 저장소에 있어서, 쓰던 창이면 빈 화면이 나오지 않는다.
- [ ] PC 폭(1024px 이상)으로 연다. 왼쪽 기록 목록과 오른쪽 채팅이 나란히 보여서, 기록이 목록에 생기는 모습을 한 화면에서 보여줄 수 있다.
- [ ] 요청 제한은 IP당 하루 30회다. 한 번 시연에 약 6회를 쓰니, 같은 날 같은 곳에서 리허설은 두세 번까지 한다.

## 흐름

| # | 할 일 | 보여줄 것 |
|---|---|---|
| 1 | 배포 주소를 연다 | 헤더에 "꼬리노트"만 있고 강아지 이름은 없다 |
| 2 | 화면을 훑는다 | 왼쪽은 "아직 기록이 없어요", 인사와 이름을 알려 달라는 예시 문장, 흐린 목록 미리보기. 오른쪽 채팅은 비어 있다 |
| 3 | 예시 문장 그대로 `안녕, 우리집 강아지 이름은 곰순이야`를 보낸다 | AI가 인사하며 이름을 저장했다고 말하고, 할 수 있는 것(기록, 설정)을 안내한다. 헤더에 "곰순이"가 붙고, 왼쪽 예시 문장이 첫 기록 문장으로 바뀐다 |
| 4 | 오른쪽 위 톱니바퀴로 설정에 간다 | 프로필 이름 칸에 "곰순이"가 들어 있다. 왼쪽 위 화살표로 돌아온다 |
| 5 | 아래 "기록 문장"을 차례로 보낸다 | 문장마다 "곰순이의 ○○을 기록했어요."와 칩 카드가 나오고, 왼쪽 목록에 바로 생긴다 |
| 6 | 진행 중 띠의 "끝"을 누른다 | 절뚝임 에피소드가 끝나고 목록에 지속시간이 붙는다 |
| 7 | 새로고침한다 | 목록, 대화, 헤더의 이름이 그대로 남아 있다 |

## 기록 문장

| 순서 | 보낼 문장 | 보여줄 것 |
|---|---|---|
| 1 | `아침 8시에 밥 먹고 산책 다녀왔어` | 빈 화면의 예시 문장 그대로. 한 문장에서 기록 두 개(식사·산책), 시각 "08:00" |
| 2 | `방금 응가했는데 좀 무른 편이야` | 표현 정규화("무른 편" → 무름), 횟수 1회 기본값 |
| 3 | `천둥 쳐서 5분 동안 떨었어` | 에피소드와 지속시간 5분 |
| 4 | `곰순이 간식으로 개껌 줬어` | 이름을 기록 내용으로 보지 않고 간식으로 기록 |
| 5 | `왼쪽 뒷다리를 절뚝거려` | 끝나지 않은 에피소드라 입력창 위에 "진행 중" 띠가 뜬다 |

마지막 문장을 5번에 둬서, 바로 이어 6단계에서 진행 중 띠를 끝낸다.

## 피할 것

- 초콜릿·포도 같은 위험 음식 문장: 기록은 되지만 위험 안내(`assess()`)가 없어서 경고 없이 저장된다.
- `오늘 설사 2번 했어`처럼 횟수를 말한 하루 단위 문장: 횟수를 이미 말했는데도 "몇 번인지 남기시려면…" 안내가 붙는다.
- 질문·상담("지난주 배변 어땠어?"): 아직 준비 중이라는 답만 나온다.
