## 계획

- 목표: 화면 너비 1024px(`lg`) 이상에서 왼쪽에 기록 목록, 오른쪽에 채팅을 고정한다. 좁은 화면은 지금 동작(입력창 → 채팅 시트)을 그대로 둔다.
- 근거: PRD R0. 원래 R0는 "입력창을 누르면 채팅이 아래에서 올라온다"뿐이라 넓은 화면 규칙을 R0에 추가했다.
- 수정할 파일: `src/app/layout.tsx`, `src/app/settings/page.tsx`, `src/components/preview/PreviewCatalog.tsx`, `src/components/chat/ChatPanel.tsx`(새 파일), `src/components/MainScreen.tsx`, `docs/PRD.md`
- 완료 기준: 360px는 이전과 같다. 1024px 이상에서 두 영역이 나란히 보이고, 오른쪽 채팅에서 저장·되돌리기한 기록이 왼쪽 목록에 바로 반영된다. `lint`, `typecheck`, `test`, `build` 통과.
- 범위 밖: 저장소·파싱·상담 로직, 768~1023px 전용 배치, 패널 크기 조절.

## 결과

- 한 일: 루트 레이아웃의 `max-w-md`를 각 화면으로 옮겼다. 메인을 `lg` 이상에서 2단 그리드로 바꾸고, 채팅 패널(`ChatPanel`)을 새로 만들었다. 좁은 화면의 입력창과 채팅 시트는 `lg:hidden`으로 숨긴다.
- 결정과 맞바꾼 것:
  - 1024px vs 768px 기준: 768px에서는 왼쪽 목록이 약 350px로 좁아져 1024px를 골랐다. 대신 태블릿 세로 화면은 휴대폰 배치를 쓴다.
  - 화면 전환은 CSS로만 한다. JS 미디어 쿼리를 쓰지 않아 서버 렌더링과 화면이 어긋날 일이 없다. 대신 채팅 내용(`ChatView`)은 두 곳에 놓이지만, 시트가 닫혀 있으면 그리지 않아 실제로는 한 번만 그린다.
- 계획과 달라진 점: `ChatPanel`을 휴대폰 시트와 같이 쓰려 했으나, 시트(`BottomSheet`)는 그대로 두고 채팅 내용만 함께 쓰게 했다. 시트에는 넓은 화면에서 숨기기 위한 `className` 옵션만 더했다.
- AI가 틀렸다가 고친 것:
  - 정리 도구: 프로젝트에 없는 Prettier를 실행해 `MainScreen.tsx` 전체가 80칸 폭으로 다시 정렬됐다 → 손대지 않은 함수까지 바뀐 것을 확인 → 기존 코드 폭(120칸)에 맞춰 다시 정렬하고, 바꾸지 않은 함수는 원래 모양으로 되돌렸다.
  - 커밋 분할: zsh에서 파일 목록 변수가 한 덩어리로 넘어가 백업 복사가 실패했다 → 실패 출력에서 아무 파일도 바뀌지 않은 것을 확인 → bash로 다시 실행했다.
- 확인하지 못한 것: 브라우저 확장이 연결되지 않아 실제 화면(360px, 1280px)은 직접 보지 못했다.
