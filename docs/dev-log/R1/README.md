# R1 채팅 입력: 기록과 상담 나누기, 기록 저장

- 시작: 2026-11-01
- 근거: `docs/prd/R1.md`
- 목표: 채팅으로 보낸 메시지를 의도에 따라 나누고, 기록이면 칩으로 바로 저장해 고정 문장으로 답한다. 가짜 데이터로 움직이는 메인 화면을 실제 저장소와 파싱에 연결한다.
- 범위 밖: 상담 답변 생성(R4), 위험 판단과 양·종류 보충(R6), 표현 사전 20~30개와 추정 시각(R8, R2. R1은 최소 버전), 에피소드(R12), 종류 편집 화면(R11 P2)
- 블로킹 질문: 없음

## 요구사항별 개발

| 하위 요구사항 | 어떻게 만드나 | 하위 작업 | 확인 |
|---|---|---|---|
| R1-1 입력 수단 | 입력창 → 처리 파이프라인 연결 | 5 | 수동 확인 |
| R1-2 의도 나누기 | `classifyIntent`: 문장 끝 질문·인사·칩 완성 규칙. 나머지는 파싱 API | 3, 4 | 테스트. R1-2.3의 상담 답변 부분은 R4 이후 |
| R1-3 인사만 있는 메시지 | 인사 판별 + 고정 문장 두 개 | 3 | 테스트 |
| R1-4 기록 처리 순서 | 최소 사전(`lexicon.ts`)·시각 파서(`parseTime`) → 종류와 핵심 항목이 채워지면 `needsLlm = false`. 핵심 항목은 종류 정의의 `core` | 2 | 테스트 |
| R1-5 LLM 실패 처리 | 파싱 API 실패 시 사전 칩 저장, 시각 미정이면 입력 시각 + 추정, 의도를 못 정하면 메모 저장 + 고정 문장 | 4 | 테스트 |
| R1-6 바로 저장 | 화면을 `saveEntry`/`deleteEntry`에 연결, 칩 수정·되돌리기 | 5 | 수동 확인 |
| R1-7 기록 응답 | `recordReply`: 종류만 묶은 확인 문장 + 빈 핵심 항목의 `askHint` | 2 | 테스트 |
| R1-8 한 문장에 기록 여러 개 | `extractEntries`: 종류마다 기록 하나, 값은 그 항목을 가진 종류에, 둘 이상이면 `needsLlm`, 시각 공유 | 2 | 테스트 |
| R1-9 모호한 칸 | R1에서 만들지 않음 | - | R8, R6 |
| R1-10 강아지 이름 제외 | `extractEntries` 안에서 이름 뒤 조사로 강아지·음식 판단 | 2 | 테스트 |
| R1-11 기록은 기록 메시지에서만 | 채팅 메시지를 블록 단위로 저장, 상담·기타는 기록을 만들지 않음 | 1, 5 | 테스트 + 수동 확인 |
| R1-12 이전 대화 제외 | 파싱 요청에 현재 메시지만 넣음 | 4 | 테스트 |

## 하위 작업

수락 기준 묶음 하나가 하위 작업 하나다. 위에서부터 한다. 시작하면 하위 문서를 링크하고, 끝나면 체크한다.

- [x] 1. [저장 구조](storage-shape.md): 종류 정의 데이터(기본 9개, 내용은 지금 값 목록 그대로), 기록 = 종류 id + 항목 값, 채팅 메시지 블록 저장. ADR 2개(종류 정의 데이터, 채팅 메시지 저장)를 먼저 쓴다 — 채우는 수락 기준: R1-11.1의 저장 부분, R11 기반
- [x] 2. [칩 만들기와 기록 응답](chip-extraction.md): 종류 정의에 핵심 항목·기본값·안내 문구, 최소 사전·시각 파서, 이름 제외, 여러 기록 나누기, 고정 응답 문장 — 채우는 수락 기준: R1-4.1, R1-4.2, R1-7.1, R1-7.2, R1-7.3, R1-8.1, R1-8.2, R1-10.1, R1-10.2, R11 "배변 횟수 1회"
- [ ] 3. 의도 나누기(코드): 확실한 경우 규칙, 인사 처리, 의도 테스트. 테스트에서 정확도가 떨어지면 코드 규칙을 줄이고 LLM이 고르는 비중을 늘린다(2026-11-01 결정) — 채우는 수락 기준: R1-2.1, R1-2.2, R1-3.1
- [ ] 4. 파싱 API: 의도와 빈 칸을 한 번에 받는 LLM 호출, 실패 처리, 이전 대화 제외 — 채우는 수락 기준: R1-5.1, R1-5.2, R1-5.3, R1-12.1
- [ ] 5. 화면 연결: Home을 저장소와 파이프라인에 연결, 바로 저장·고치기·되돌리기, 새로고침 후 채팅 유지, 메인 목록 오름차순·처음부터 맨 아래(R0), 하루 전체 기록 "종일"·그날 맨 아래(R11). 수정 시트에서 하루 전체를 고르는 방법(열린 질문)은 R1-6에서 정한다 — 채우는 수락 기준: R1-1.1, R1-6.1, R1-11.1, R1-2.3(기록 부분), R0 목록 순서, R11 "종일" 표시
