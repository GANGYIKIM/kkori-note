## 계획

개발 사양이다. 승인 요청도 이 형식으로 한다. 결정 과정(고른 것·버린 것)은 적지 않는다. ADR에 쓰거나, 작은 결정이면 마친 뒤 결과의 "결정과 맞바꾼 것"에 쓴다. 마칠 때 실제로 만든 것과 다르면 맞추고, 다른 이유는 결과의 "계획과 달라진 점"에 쓴다. 마친 뒤 다시 손볼 때는 계획을 고치지 않는다.

### 만들 것

작업이 끝나면 코드에 무엇이 있는지 적는다. 읽는 사람이 다르게 해석할 수 없게 쓴다.

- 대상(파일, 타입, 함수, 화면)마다 굵은 글씨로 묶는다.
- 타입·함수는 이름으로 적고, 무엇을 받아 무엇을 돌려주는지, 실패하면 어떻게 되는지 적는다.
- 바뀐 뒤 모습만 적는다. 없애는 것은 "없애는 것"으로 따로 묶는다.
- 값 목록·항목처럼 여럿인 것은 표나 목록으로 다 적는다. "…", "등"을 쓰지 않는다.
- 이유는 적지 않는다.

### 바꾸는 곳

새로 만들거나 모양(export, 스키마, 인터페이스)이 바뀌는 파일만 적는다. 그것을 쓰는 파일은 적지 않는다.
