# ADR-0001: LLM 모델 선택 — 기록 파싱은 gpt-6-luna, 상담은 gpt-6.1-terra

- **Status:** Accepted
- **Date:** 2026-10-29
- **Confidence:** Medium (한국어 분류·상담 품질과 실제 API 호출을 아직 확인하지 못한 잠정 결정)

## Decision

**기록 파싱(R1, R2, R8)에는 `gpt-6-luna`(추론 강도 `none`), 상담(R4, R5, R6의 문장 생성)에는 `gpt-6.1-terra`(추론 강도 `low`)를 쓴다.** 파싱은 문장을 값 목록으로 분류하는 단순 작업이라 가장 저렴한 모델을, 상담은 모드별 말투와 근거를 엮어 쓰는 작업이라 글쓰기에 강점이 있다고 소개된 모델을 고른다. 모델명과 추론 강도는 코드에 박지 않고 환경변수로만 지정한다.

## Context

- 꼬리노트는 LLM을 두 곳에서 쓴다. (1) 사용자가 입력한 문장을 구조화 칩으로 변환(호출 빈도 높음, 출력이 값 목록으로 제한됨), (2) 저장된 기록을 근거로 한 상담 답변(호출 빈도 낮음, 자연스러운 문장 필요).
- 제약: 개인 과제 5일, Vercel 공개 배포로 누구나 호출 경로에 접근 가능, OpenAI 선불(충전식) 크레딧. 그래서 비용 상한이 중요하고, 요청 횟수 제한(PRD R9)을 함께 둔다.
- 모델명과 가격은 자주 바뀌고, 검색 중 만난 제3자 블로그들은 서로 모델명이 달라 신뢰하지 않았다. 그래서 OpenAI 공식 문서(developers.openai.com)만 근거로 삼았다.
- 모델은 작업 성격(분류 vs 글쓰기)에 따라 나누며, 같은 종류의 작업 안에서는 입력 내용과 무관하게 항상 같은 모델을 쓴다. (결과의 일관성을 위해 입력별로 모델을 바꾸지 않는다.)

## Candidates

공식 문서에서 직접 읽은 모델만 적는다. 가격은 입력 / 출력 (USD, 1M 토큰 기준).

### A. gpt-6-luna — $0.10 / $0.50
- "가장 효율적인 모델, 집중된 고빈도 작업용". 구조화 출력·스트리밍·함수 호출 지원, Chat Completions 지원.
- 추론 강도 기본값 `medium`. Chat Completions에서 함수 호출은 추론 강도 `none`일 때만 지원.
- 한국어 지원에 대한 언급은 문서에 없음.

### B. gpt-6.1-terra — $1.00 / $5.00
- "빠르고 효율적인 모델, 시각 추론·정밀한 컴퓨터 사용·명확하고 자연스러운 글쓰기". 구조화 출력 지원, Chat Completions와 Responses 지원.
- 추론 강도 기본값 `medium`. 문서에 도구 호출은 Responses API가 필요하다고 명시.

### C. gpt-6.1-sol — $2.00 / $10.00
- 가격 페이지에서 가격만 확인했고 모델 상세 페이지는 읽지 않았다. 상담 품질이 부족할 때 올릴 후보로만 남긴다.

### D. gpt-5.4-mini — $0.75 / $4.50
- 이전 세대 mini. 구조화 출력·Chat Completions 지원, 지원 중단 표시 없음. 같은 용도에서 Luna보다 비싸서 채택하지 않았다.

### E. gpt-5.4-nano — $0.20 / $1.25
- 모델 페이지에 지원 중단(deprecated)으로 표시되어 제외.

## Evaluation

가격과 기능은 2026-10-29에 OpenAI 공식 문서에서 읽은 값이다. 가격 페이지에는 게시일이 표시되어 있지 않다.

- 가격 페이지: <https://developers.openai.com/api/docs/pricing>
- 모델 페이지: [gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [gpt-6.1-terra](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [gpt-5.4-mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), [gpt-5.4-nano](https://developers.openai.com/api/docs/models/gpt-5.4-nano)

**비용 추정** (실측이 아니라 위 가격으로 계산한 값. 내부 추론 토큰은 제외하며, 토큰 수는 가정이다.)

| 호출 | 가정 | 모델 | 1회 추정 |
|---|---|---|---|
| 기록 파싱 | 입력 500 / 출력 150 토큰 | gpt-6-luna | 약 $0.000125 |
| 상담 | 입력 2,000 / 출력 500 토큰 | gpt-6.1-terra | 약 $0.0045 |

서버 전체 하루 상한(500회, PRD R9)이 모두 상담 호출이라고 가정하면 하루 약 $2.25이다. 추론 토큰이 붙으면 이보다 늘 수 있다.

**확인한 것** (2026-10-29, 로컬 개발 서버의 `/api/llm-check`를 터미널에서 직접 호출. 질문은 한국어 인사말 한 줄이며, 결과는 김강이가 터미널 출력으로 확인함)
- `gpt-6-luna` + 추론 강도 `none` (Chat Completions): 한국어 한 문장 응답 정상. 모델명, API 키, `reasoning_effort: none` 파라미터가 모두 오류 없이 받아들여짐.
- `gpt-6.1-terra` + 추론 강도 `low` (Chat Completions): 한국어 한 문장 응답 정상.
- 서버 라우트의 입력 길이·횟수 제한과 설정 누락(503) 응답은 로컬에서 확인함.
- 위 호출은 일반 텍스트 응답이라, 아래 "측정하지 않은 것"의 구조화 출력 항목과는 별개다.

**측정하지 않은 것**
- 한국어 표현 분류 정확도 (표현 사전 테스트 미실행)
- 상담 답변 품질과 모드별 일관성 (안전 평가 케이스 미실행)
- 응답 지연 시간
- 구조화 출력(Zod 스키마)이 두 모델에서 기대대로 동작하는지 (아직 구현 전)
- Vercel 배포 환경에서의 API 호출 (배포 후 확인 예정)

## 확인하지 않은 가정

| ID | 가정 | 확인 방법 |
|---|---|---|
| A1 | `gpt-6-luna`의 한국어 표현 분류가 충분히 정확하다 | 표현 사전 테스트 (M1) |
| A2 | `gpt-6.1-terra`의 상담 품질과 모드별 일관성이 충분하다 | 안전 평가 케이스 (M2) |
| A3 | 응답 지연 시간이 문제 되지 않는다 | 측정 방법 미정 |
| A4 | 구조화 출력(Zod 스키마)이 두 모델에서 기대대로 동작한다 | 구현 후 확인 |
| A5 | Vercel 배포 환경에서도 API 호출이 동작한다 | 배포 후 확인 |

## Consequences

- 파싱 비용이 매우 낮아 호출이 잦아도 부담이 작다. 상담은 상대적으로 비싸지만 호출 빈도가 낮다.
- 한국어 품질이 검증되지 않은 상태로 시작하므로, 표현 사전 테스트가 이 결정의 검증 수단이 된다.
- 두 모델 모두 기본 추론 강도가 `medium`이라 그대로 두면 비용과 지연이 늘어난다. 그래서 파싱 `none`, 상담 `low`를 기본값으로 두고 환경변수(`OPENAI_REASONING_PARSE`, `OPENAI_REASONING_CONSULT`)로 조정한다. 상담의 `low`는 임의로 정한 시작값이다.
- 문서상 도구 호출(웹 검색 등)은 Responses API가 필요하다. 웹 검색 연동(PRD P3)을 넣을 때 해당 호출만 Responses API로 바꿔야 한다. 지금 코드는 Chat Completions를 쓴다.
- 모델명이 환경변수라 모델을 바꿀 때 코드 수정이 필요 없다. 대신 Vercel과 로컬 `.env.local` 양쪽에 같은 값을 넣어야 한다.
- 모델이 지원 중단되거나 가격이 바뀔 수 있으므로 배포 직전에 가격 페이지를 다시 확인한다.

## Re-evaluation Triggers

- 표현 사전 테스트에서 `gpt-6-luna`의 분류가 기대 값과 자주 어긋난다면 → 파싱도 `gpt-6.1-terra`로 올린다. (통과 기준은 첫 실행 결과를 보고 확정, `docs/metrics.md`의 M1 참고)
- 안전 평가 케이스에서 모드 간 모순이나 상담 품질 문제가 `gpt-6.1-terra`에서 반복된다면 → `gpt-6.1-sol` 등 상위 모델이나 추론 강도 상향을 검토한다.
- 웹 검색 연동(P3)을 도입할 때 → 해당 호출을 Responses API로 전환하는 별도 ADR을 쓴다.
- 선택한 모델이 지원 중단되거나 가격이 크게 바뀔 때.
- 실제 사용에서 일일 비용이 추정치를 크게 넘을 때.
