# ADR-0015: 스크롤바는 기본 스크롤바를 숨기고 직접 만든 오버레이 막대로 보여준다

- **Status:** Accepted
- **Date:** 2026-11-02
- **Confidence:** Medium (동작이 단순해 직접 만들 수 있다고 봤지만, 터치 기기와 여러 브라우저에서 아직 확인하지 않았다)

## Decision

**모든 스크롤 영역에서 브라우저 기본 스크롤바를 CSS로 숨기고, 라이브러리 없이 직접 만든 얇은 오버레이 막대를 내용 위에 띄운다.** 스크롤바가 화면 폭을 차지해 내용이 줄거나 밀리는 것을 없애고, 필요한 동작(보이기·사라지기·끌기)이 단순해 라이브러리를 들일 만큼 크지 않아서다.

## Context

- 스크롤바가 항상 보이는 환경(Windows Chrome 등)에서는 기본 스크롤바가 폭을 따로 차지해 스크롤이 생기면 내용 폭이 바뀐다. 사용자는 스크롤바가 고정 폭을 잡는 것을 원하지 않았다(2026-11-02 대화).
- 스크롤 영역은 문서 전체(모바일·태블릿 메인, 설정), PC 목록 칸(`src/components/main/Home.tsx`), PC 채팅 칸(`src/components/layout/SidePanel.tsx`), 시트 본문(`src/components/layout/BottomSheet.tsx`)이다(2026-11-02 확인).
- 데이터를 나눠 그리는 가상 스크롤은 이번에 하지 않고 R0 "나중에"로 미뤘다.
- 스택 밖 라이브러리는 이유와 함께 먼저 제안한다(CLAUDE.md).

## Candidates

### A. 기본 스크롤바 숨기기 + 직접 만든 오버레이 막대 (채택)
- 라이브러리가 없다. 동작(스크롤·마우스 올림에 보이기, 1초 뒤 사라지기, 끌기)만 만든다.
- 빈 홈 클릭, 키보드 조작은 만들지 않고 브라우저 기본 스크롤에 맡긴다.

### B. 오버레이 스크롤바 라이브러리 (OverlayScrollbars, SimpleBar)
- 여러 브라우저와 터치를 다뤄 주지만 스택 밖 의존성이 늘고, 필요한 동작에 비해 커서 탈락했다.

### C. 스크롤바만 숨기기 (`scrollbar-width: none`)
- 폭 문제는 없지만 긴 목록에서 위치를 알 수 없어 탈락했다.

### D. 얇게만 (`scrollbar-width: thin`)
- 폭이 줄 뿐 여전히 차지해서 탈락했다.

## Evaluation

측정하지 않음.

## 확인하지 않은 가정

| ID | 가정 | 확인 방법 |
|---|---|---|
| A1 | 기본 스크롤바를 숨겨도 휠·터치·키보드 스크롤은 그대로 동작한다 | Chrome·Safari·모바일에서 메인과 시트를 스크롤해 본다 |
| A2 | 문서 전체 스크롤에도 같은 막대를 붙일 수 있다 | 모바일 메인에서 막대가 보이는지 확인한다 |

## Consequences

- 스크롤 영역마다 같은 오버레이 막대 컴포넌트를 쓴다. 새 스크롤 영역도 이 컴포넌트를 쓴다.
- 기본 스크롤바를 숨기는 CSS가 전역에 들어간다.
- 맞바꾼 것: 빈 홈 클릭으로 한 페이지씩 넘기기, 스크린 리더용 스크롤바 표시는 하지 않는다. 브라우저마다 다른 기본 스크롤바의 접근성 동작을 직접 맞추지 않는다.

## Re-evaluation Triggers

- 터치 기기나 특정 브라우저에서 스크롤이 끊기거나 막대가 어긋날 때 (A1, A2)
- 가상 스크롤을 도입할 때(목록 높이를 직접 계산하게 되면 막대 계산도 함께 본다)
- 빈 홈 클릭이나 키보드 조작 요구가 생길 때
