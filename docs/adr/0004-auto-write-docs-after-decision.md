# ADR-0004: 결정이 나면 문서는 묻지 않고 쓰고, ADR은 고치지 않고 대체한다

- **Status:** Accepted
- **Date:** 2026-10-30
- **Confidence:** Medium (자동으로 쓴 문서가 사용자가 원하는 수준인지 아직 확인하지 않음)

## Decision

**결정이 확정되거나 작업이 끝나면 AI는 CLAUDE.md 문서 표의 "쓸 때"에 해당하는 문서를 묻지 않고 쓴다.** 결정 자체는 지금처럼 사용자에게 묻는다. 함께 문서 관리 규칙을 정한다. Accepted ADR은 본문을 고치지 않고 새 ADR로 대체한다. ADR의 추측은 표시한다. 작성자 칸은 없앤다. ADR과 dev-log에는 색인을 둔다. ADR-0002의 "ADR은 승인 후 쓴다"를 대체한다.

## Context

- CLAUDE.md는 "ADR이나 PRD 수정이 필요한지는 아래 문서 표로 판단한다"고만 해서, 문서를 쓰라는 건지 쓸지 물으라는 건지 모호했다. ADR 행의 "승인 후"는 결정 승인과 별도로 ADR 작성 승인을 받으라는 뜻으로 읽혔다.
- 사용자는 결정이 나면 문서가 자동으로 쌓이기를 원했다. 또 규칙이 바뀔 때마다 기존 ADR 내용이 바뀌는 것을 원하지 않았다.
- ADR 0001~0003의 `Decision makers`는 모두 같은 한 사람이다. 1인 프로젝트라 이 칸이 담는 정보가 없다.
- ADR과 dev-log는 지금까지 파일 이름으로 찾았다. 문서가 쌓이면 찾을 때 여러 파일을 열어 보게 된다.

## Candidates

### 문서 작성 시점
- **A. 결정이 확정되면 묻지 않고 쓴다 (채택)**: 사용자는 결정만 하고 기록은 AI가 한다. 쓴 문서는 마지막 답변에 경로로 알려서 사용자가 확인할 수 있다.
- **B. 문서를 쓸 때마다 승인받는다 (기존)**: 결정 승인과 문서 승인을 두 번 받게 되어 탈락했다.

### 기존 ADR을 바꾸는 방식
- **A. 새 ADR로 대체하고 옛 ADR은 Status 줄만 바꾼다 (채택)**: 당시 판단 근거가 남는다. 최신 결정은 번호와 Status로 알 수 있다.
- **B. 기존 ADR 본문을 고친다**: 이전 근거가 사라져서 탈락했다.
- **C. 파일에 버전(v1, v2)을 붙인다**: 같은 결정이 여러 파일로 흩어지고, 글자 단위 변경 이력은 이미 git에 있어서 탈락했다.

### 추측 표시
- **A. 본문에 `(추측 A1)`을 붙이고 "확인하지 않은 가정" 표에 확인 방법과 함께 모은다 (채택)**: 무엇을 확인해야 하는지 한 곳에서 보이고, Re-evaluation Triggers와 이을 수 있다.
- **B. 본문에만 "(추측)"을 붙인다**: 확인할 것이 본문에 흩어져서 탈락했다.

### 찾기
- **A. 폴더마다 `README.md` 색인 + 색인 누락 테스트 (채택)**: 손으로 관리하는 색인은 어긋나기 쉬워서 테스트로 막는다.
- **B. 파일 이름으로 찾기 (기존)**: 문서가 늘면 여러 파일을 열어야 해서 탈락했다.

## Evaluation

측정하지 않음.

## 확인하지 않은 가정

없음.

## Consequences

- CLAUDE.md "끝낼 때"에 자동 작성 규칙을 더하고, 문서 표의 ADR·dev-log 행이 각 폴더의 `README.md`를 가리키게 한다.
- 새 파일: `docs/adr/TEMPLATE.md`, `docs/adr/README.md`, `docs/dev-log/README.md`, `tests/docs-index.test.ts`.
- 템플릿이 바뀌면 기존 ADR의 형식은 맞춰도 된다. 결정 내용과 근거는 바꾸지 않는다. 이 규칙에 따라 0001~0003에서 `Decision makers` 줄을 지우고 "확인하지 않은 가정" 칸을 더했다. 가정 칸에는 본문에 이미 "측정하지 않음"이나 "확인하지 않음"으로 적혀 있던 것만 옮겼다.
- 맞바꾼 것: 사용자가 문서를 쓰기 전에 보지 못한다. 대신 답변에 경로가 남아 나중에 고칠 수 있다.

## Re-evaluation Triggers

- 자동으로 쓴 문서를 사용자가 되돌리거나 크게 고친 일이 반복될 때
- 여러 사람이 함께 작업하게 되어 결정한 사람을 구분해야 할 때 (작성자 칸을 되살린다)
