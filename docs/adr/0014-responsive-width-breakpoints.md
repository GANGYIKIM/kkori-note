# ADR-0014: 화면 폭을 모바일·태블릿·PC 세 구간으로 나누고, 폭은 %·최대 폭은 px로 정한다

- **Status:** Accepted
- **Date:** 2026-11-02
- **Confidence:** Medium (값은 계산으로만 골랐고, 태블릿·PC 실제 화면에서 아직 보지 않았다)

## Decision

**화면 폭으로만 모바일(~767px)·태블릿(768~1023px)·PC(1024px~)를 나눈다. 폭은 %로, 최대 폭은 px로 정한다. 모바일·태블릿은 1단 92%, PC는 2단 전체 92%·최대 1200px 가운데 정렬, 채팅 칸 40%·최대 420px, 설정 화면은 92%·최대 672px이다.** 모든 구간에서 고정 448px 기둥 때문에 태블릿과 화면 분할 창의 양옆이 비는 것을 없애고, PC에서는 너무 넓어지지 않게 하기 위해서다.

## Context

- 처음 화면을 만들 때 휴대폰만 생각해 루트 레이아웃에 `max-w-md`(448px)를 걸었다(커밋 `1835522`). 넓은 화면 2단 배치 때 이 값을 각 화면으로 옮기고 1024px 이상에서만 풀었다(`docs/dev-log/2026-10-29-wide-screen-layout.md`). 448px를 고른 근거는 문서에 없다.
- 그래서 448~1023px 창(태블릿, 가로 휴대폰, 화면 분할)에서 목록이 448px로 고정되고 양옆이 빈다. 900px 창에서 양옆 여백이 각 226px다(2026-11-02 `src/components/main/Home.tsx` 기준 계산).
- PC 2단은 창 전체를 쓰고 채팅 칸이 창 오른쪽 끝에 420px로 붙는다. 목록만 최대 672px(`lg:max-w-2xl`)다 (`src/components/main/Home.tsx`, 2026-11-02 확인).
- 사용자가 정한 원칙(2026-11-02 대화): PC·태블릿·모바일을 모두 고려하되 화면 폭 기준 최적화일 뿐 기기 특성(터치, 입력 방식)은 보지 않는다. PC는 2단, 태블릿은 화면을 넓게 쓰는 1단 목록, 모바일은 1단. PC는 최대 폭을 두고 가운데 정렬한다.
- 최소 폭은 320px이고 더 좁으면 가로 스크롤이 생긴다(R0, 2026-11-02).

## Candidates

### 구간 경계

#### A. 모바일 ~767px, 태블릿 768~1023px, PC 1024px~ (채택)
- Tailwind 기본 기준(`md` 768, `lg` 1024)과 같다. PC 2단 기준 1024px는 이미 쓰고 있다.

#### B. 모바일 ~599px, 태블릿 600~1023px, PC 1024px~
- 폴더블·화면 분할 창도 태블릿처럼 쓰지만 기준을 새로 정의해야 해서 탈락했다.

### 모바일·태블릿 내용 폭

#### A. 둘 다 92% (채택)
- 390px에서 양옆 16px로 지금과 같고, 태블릿(768~1023px)은 양옆 31~41px만 남긴다. 값이 하나다.

#### B. 모바일 92%, 태블릿 90%
- 태블릿 여백이 조금 늘 뿐 차이가 작아 탈락했다.

#### C. 448px 고정 + 좌우 16px (지금)
- 태블릿·화면 분할에서 양옆이 비어 탈락했다.

### PC 2단 최대 폭

#### A. 1200px (채택)
- 채팅 420px일 때 목록 780px. 노트북(1280~1440px)에서도 양옆 여백이 남아 가운데 정렬이 보인다.

#### B. 1280px, C. 1440px
- 목록이 더 넓어지고, 1440px는 노트북에서 사실상 92%라 최대 폭의 의미가 약해 탈락했다.

### PC 채팅 칸 폭

#### A. 40%, 최대 420px (채택)
- 1024px 창(2단 942px)에서 채팅 377px·목록 565px. 2단이 1050px 이상이면 채팅 420px.

#### B. 35%, 최대 420px
- 1024px 창에서 채팅 330px로 휴대폰 내용 폭(359px)보다 좁아져 탈락했다.

#### C. 420px 고정
- 지금과 같지만 "폭은 %" 규칙의 예외가 되어 탈락했다.

## Evaluation

측정하지 않음. 위 폭은 창 폭에 비율을 곱해 계산한 값이다.

## 확인하지 않은 가정

| ID | 가정 | 확인 방법 |
|---|---|---|
| A1 | 377px 채팅 칸에서 칩 카드·말풍선이 휴대폰처럼 깨지지 않는다 | 1024px 창에서 `/preview`와 메인을 열어 본다 |
| A2 | 태블릿에서 92% 폭 목록의 한 줄 길이가 읽기에 불편하지 않다 | 768px, 1023px 창에서 기록 목록을 본다 |

## Consequences

- 고정 448px(`max-w-md`)를 화면 레이아웃에서 없앤다. 메인 목록·헤더 안쪽·하단 입력창은 92%, 채팅 시트는 판 자체가 창 폭 100%이고 안쪽 내용이 92%다. 설정 화면은 92%·최대 672px다.
- PC 2단은 전체가 92%·최대 1200px로 가운데에 놓이고, 채팅 칸은 창 오른쪽 끝에서 떨어진다.
- 개발용 미리보기 화면(`/preview`)은 이 규칙에서 뺀다.
- 맞바꾼 것: 320px 창에서 양옆 여백이 16px에서 13px로 줄어든다. 태블릿에는 최대 폭이 없어 1023px 창에서 목록이 941px까지 넓어진다.

## Re-evaluation Triggers

- 태블릿이나 1024px 근처 PC 화면에서 목록 줄이 너무 길거나 채팅 칸이 좁다는 문제가 보일 때 (A1, A2)
- 모바일 앱 출시 등으로 기기 특성(터치, 안전 영역)을 고려해야 할 때
- 768px 근처 창(화면 분할)에서 1단이 불편해 2단 기준을 낮추자는 요구가 생길 때
