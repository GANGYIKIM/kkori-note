# R1. 채팅 입력: 기록과 상담 나누기, 기록 저장

> 색인: `docs/PRD.md` / 자주 함께 보는 R: R2, R6, R7, R8, R11, R12

## 사용자 스토리

- 보호자로서, "방금 배변했는데 무른 편이야"처럼 한 문장을 입력해 기록하고 싶다. 타이핑만으로 빠르게 남기기 위해서다.
- 보호자로서, 저장된 요약 칩("발작 · 방금 · 약 2분")을 보고 틀린 칸만 바로 고치거나 되돌리고 싶다. AI의 해석 오류가 그대로 남지 않게 하기 위해서다.
- (P2) 보호자로서, 칩을 탭하는 대신 "아니 30분 전이야"처럼 채팅으로 말해 칩을 고치고 싶다.
- (P2) 보호자로서, 산책 중 손이 바쁠 때 음성으로 기록하고 싶다.

## 요구사항 (P1)

기록 종류와 종류별 항목은 R11, 에피소드 열기·닫기는 R12를 따른다.

- **R1-1 입력 수단**: 텍스트 채팅 입력이 1순위 입력이다. (음성은 P2)
  - 수락 기준
    - [ ] R1-1.1 입력창에 텍스트를 보내면 기록·상담으로 처리된다. 음성 입력은 없다.
- **R1-2 의도 나누기**: 메시지 하나를 `기록` / `상담` / `기록+상담` / `기타(인사 등)` 중 하나로 나눈다.
  - ① 코드는 확실한 경우만 정한다: 문장 끝이 질문("?", "보여줘", "알려줘", "어때", "어땠어" 등)이면 상담, 인사만 있으면 기타, 사전(R8)과 시각 파서(R2)로 칩이 다 채워지면 기록, 문장 끝이 질문이면서 칩이 다 채워지면 기록+상담. 신호 단어가 문장 중간에만 있으면("설사 이제 괜찮아졌어", "왜인지 밥을 반만 먹었어") 코드가 정하지 않는다.
  - ② 그 밖은 LLM(파싱용 모델)이 값 목록 안에서 고른다. 기록이면 빈 칸도 같은 호출에서 채운다.
  - ③ **그래도 애매하면 기록으로 본다.** 칩을 보고 사용자가 고치면 된다.
  - 인사가 섞여 있으면 인사는 빼고 나머지 내용으로 나눈다. 예: "안녕! 이번주 배변 기록 보여줘"는 인사가 아니라 나머지 내용으로 나눈다.
  - 수락 기준
    - [ ] R1-2.1 문장 30개 정도와 기대 의도를 비교하는 **의도 테스트**가 자동으로 통과한다. 신호 단어가 문장 중간에만 있는 문장("설사 이제 괜찮아졌어")과 인사가 섞인 문장을 포함한다.
    - [ ] R1-2.2 "지난주 배변 어땠어?"는 기록을 만들지 않고 상담으로 처리된다.
    - [ ] R1-2.3 "오늘 설사했는데 왜 그럴까?"는 설사 칩 저장과 상담 답변이 함께 나온다.
- **R1-3 인사만 있는 메시지**: 인사만 있는 메시지에는 코드의 고정 문장을 두 채팅으로 나눠 답한다(LLM을 쓰지 않음). 채팅 1: "안녕하세요! 기록하거나 궁금한 걸 물어보세요." 채팅 2: "예: '방금 배변했는데 무른 편', '지난주 배변 어땠어?'"
  - 수락 기준
    - [ ] R1-3.1 "안녕"에는 LLM 호출 없이 고정 문장 두 채팅이 나온다.
- **R1-4 기록 처리 순서**: ① 키워드 사전(R8)과 시각 파서(R2)로 먼저 채운다 → ② 종류와 핵심 항목(R11)이 모두 채워지면 **LLM을 호출하지 않는다** → ③ 빈 칸이 남을 때만 LLM이 Zod 스키마로 검증된 구조화 출력을 낸다. 비용과 요청 제한 소모를 줄이기 위해서다.
  - R1의 시각 파서는 최소로 만들고 R2에서 넓힌다. 표현이 없거나 "방금"·"지금"이면 지금, "N분 전"·"N시간 전"이면 그만큼 앞선 시각, "하루종일"·"오늘 하루"면 오늘 하루 전체 기록이다. 시각 없이 "오늘"만 있으면 오늘 하루 전체 기록으로 두고 LLM을 부르지 않는다(응답 안내는 R1-7). 그 밖의 시각 표현("아까", "어제 저녁쯤")은 시각이 비었다고 보고 LLM에 맡긴다. 절뚝임·발작·천둥 떨림 기록에서 "전"이 붙지 않은 "N분", "N초", "N시간"(쯤·정도·동안이 붙어도 됨)은 시각이 아니라 지속시간이다.
  - 수락 기준
    - [ ] R1-4.1 "방금 배변했는데 무른 편" 입력 시 현재 시각, 배변, 무름으로 칩이 저장되고 확인 문장이 나온다. (사전으로 모두 채워지므로 LLM 호출 없음)
    - [ ] R1-4.2 "10분 전에 배변했는데 설사"는 지금보다 10분 앞선 시각으로, "배변 하루종일 3회"는 오늘 하루 전체 기록으로 저장된다.
    - [ ] R1-4.3 "발작 2분쯤 했어"는 LLM 호출 없이 지금 시각, 지속시간 2분의 발작으로 저장된다.
- **R1-5 LLM 실패 처리**: LLM 호출이 실패하거나 한도를 넘으면 사전으로 채운 칩과 원문으로 저장한다. 시각을 채우지 못했으면 입력한 시각으로 두고 칩에 "추정"으로 표시한다. 코드가 정하지 못했는데 LLM 호출이 실패하거나 한도를 넘으면 메모 기록으로 원문을 저장하고 고정 문장으로 안내한다: "지금은 내용을 정리하지 못해 메모로 남겼어요. 칩에서 종류를 고를 수 있어요."
  - 수락 기준
    - [ ] R1-5.1 LLM 호출이 실패하거나 한도를 초과해도, 사전으로 채운 칩과 원문으로 저장된다.
    - [ ] R1-5.2 코드가 의도를 정하지 못한 메시지에서 LLM 호출이 실패하면 원문이 메모 기록으로 저장되고 안내 문장이 나온다.
    - [ ] R1-5.3 "아까 배변했어"에서 LLM 호출이 실패하면 입력한 시각으로 저장되고 칩에 "추정"이 보인다.
- **R1-6 바로 저장**: 칩은 만들어지는 즉시 저장된다. 저장 버튼은 없다. 칩 카드에는 "되돌리기"가 있고, 칸을 탭해 고칠 수 있다. 고치지 않으면 그대로 기록이다.
  - 수락 기준
    - [ ] R1-6.1 칩에서 시각·값을 고치면 저장된 기록이 바뀌고, "되돌리기"로 기록을 취소할 수 있다.
- **R1-7 기록 응답**: 기록 응답 문장은 코드의 고정 문장이다(LLM을 쓰지 않음). 형식: 무엇을 기록했는지 + 비어 있는 칸이 있으면 무엇을 더 알려주면 좋은지. 예: "초코의 배변을 기록했어요. 상태(무른지, 딱딱한지)를 알려주시면 더 정확해요."
  - "무엇을 기록했는지"는 종류만 말한다. 값과 시각은 칩 카드가 보여준다. 예: "초코의 배변을 기록했어요."
  - 기록이 여러 개(R1-8)면 한 문장으로 묶는다. 예: "초코의 식사, 산책을 기록했어요."
  - "비어 있는 칸"은 비어 있는 핵심 항목이다. 위험 기록의 양·종류를 묻는 문장은 R6의 고정 문장이 맡는다.
  - 시각 없이 "오늘"만 있어 하루 전체로 둔 기록에는 칩에서 고치는 방법을 덧붙인다: "오늘 하루 몇 번인지 남기시려면 칩에서 횟수를, 대략적인 시각이 기억나시면 칩에서 시각을 고쳐 주세요." 횟수 항목이 없는 종류는 "대략적인 시각이 기억나시면 칩에서 시각을 고쳐 주세요."만 붙인다. 채팅으로 답해 칩을 고치는 것은 P2라서 칩을 안내한다. 안내 문장은 하나만 붙이고, 비어 있는 핵심 항목이 있으면 그 안내만 붙인다.
  - 수락 기준
    - [x] R1-7.1 빈 칸이 있는 기록에는 무엇을 더 알려주면 좋은지 안내가 붙는다. 예: "배변했어" → "초코의 배변을 기록했어요. 상태(무른지, 딱딱한지)를 알려주시면 더 정확해요."
    - [x] R1-7.2 "방금 배변했는데 무른 편"에는 안내 없이 "초코의 배변을 기록했어요."가, "밥 먹고 산책했어"에는 "초코의 식사, 산책을 기록했어요."가 나온다.
    - [ ] R1-7.3 "오늘 설사했어"는 LLM 호출 없이 오늘 하루 전체의 배변(설사, 1회)으로 저장되고, 응답에 칩에서 횟수와 시각을 고치는 안내가 붙는다.
- **R1-8 한 문장에 기록 여러 개**: 한 문장에 기록이 여러 개 있으면("밥 먹고 산책했어") 칩 카드를 여러 장 만든다.
  - 다른 종류마다 기록 하나를 만든다. 같은 종류가 여러 번 나오면 기록 하나다.
  - 항목 값은 그 항목을 가진 종류의 기록에 붙는다. 예: "밥 먹고 무른 변 봤어"의 "무른"은 상태 항목이 있는 배변에 붙는다. 그 항목을 가진 종류가 둘 이상이면("절뚝이고 발작했는데 심했어"의 강도) 붙이지 않고 빈 칸으로 보고 LLM에 맡긴다.
  - 시각 표현이 하나면 모든 기록에 쓰고, 없으면 지금이다. 기록마다 시각이 다르면("아침에 밥, 저녁에 산책") 시각이 비었다고 보고 LLM에 맡긴다.
  - 수락 기준
    - [ ] R1-8.1 "밥 먹고 산책했어"는 식사·산책 칩 카드 두 장으로 저장된다.
    - [ ] R1-8.2 "밥 먹고 무른 변 봤어"는 식사, 배변(무름) 칩 카드 두 장으로 저장된다.
- **R1-9 모호한 칸**: 모호한 칸은 `?` 표시와 후보 칩으로 보여주고 탭해서 고른다. 채팅으로 칩 고치기는 P2다. **예외**: 바로 앞 응답이 위험 기록의 정보(양·종류)를 물었다면, 다음 메시지의 양·종류는 새 기록이 아니라 그 기록에 붙이고 다시 판정한다(R6).
  - 확인: R8(후보 칩), R6(위험 기록 보충)의 수락 기준
- **R1-10 강아지 이름 제외**: 강아지 이름은 기록 내용으로 보지 않는다. 예: 이름이 "초코"이면 "초코가 초코 먹었어"의 앞 "초코"는 강아지, 뒤 "초코"는 음식이다.
  - 이름이 사전 단어와 겹칠 때만 이름 뒤 조사로 가른다. 가·이·는·은·도·랑·하고·와·의가 붙으면 강아지, 를·을이 붙거나 조사가 없으면 음식이다. 이름이 여러 번 나오면 하나라도 음식이면 음식이 있는 것으로 본다. 틀리면 위험 음식이 없는데 있는 쪽으로 틀리게 해 위험을 놓치지 않는다(R6).
  - 수락 기준
    - [ ] R1-10.1 "초코가 초코 먹었어"(이름 초코)는 주워 먹은 것 · 초콜릿으로 기록된다.
    - [ ] R1-10.2 이름이 초코일 때 "초코가 밥 먹었어"는 식사로, "초코가 초코를 주워먹었는데 초코가 좀 녹아있었어"는 주워 먹음 · 초콜릿으로 기록된다.
- **R1-11 기록은 기록 메시지에서만**: 기록(칩)은 기록 메시지에서만 만든다. 상담·기타(인사 등) 메시지는 기록 목록에 들어가지 않는다. 채팅 화면은 새로고침해도 남는다(R7).
  - 수락 기준
    - [ ] R1-11.1 "안녕"이나 상담 메시지는 기록 목록에 기록을 만들지 않고, 새로고침 후에도 채팅 화면에 남는다.
- **R1-12 이전 대화 제외**: 새 메시지를 처리할 때 이전 대화를 LLM에 넣지 않는다. 대화가 쌓여도 요청 하나의 비용이 늘지 않게 하기 위해서다.
  - 수락 기준
    - [ ] R1-12.1 LLM 요청에 이전 대화가 들어가지 않는다.

## 나중에

- (P2) **채팅으로 칩 고치기**: 직전 칩에 대해 "아니 30분 전이야", "설사였어"처럼 입력하면 새 기록이 아니라 그 칩을 고친다. 칩 탭 수정과 함께 쓴다. (위험 기록의 양·종류 보충은 P1 예외로 먼저 만든다, R1)
- (P2) **빠른 버튼**: 배변(상태 선택), 산책 시작/종료, 절뚝임·발작 타이머, 천둥 떨림 강도 탭. 한 손 사용을 위한 보조 입력.
- (P2) **음성 입력**: 브라우저 음성 인식(Web Speech API, Chrome 기준)으로 말한 내용을 텍스트로 변환해 같은 입력 파이프라인(R1, R2, R8)에 넣는다. 추후 앱 출시 시 1순위로 승격 가능.
