# PRD 변경 내역

PRD(`docs/PRD.md`, `docs/prd/`)를 고칠 때 맨 아래에 한 줄씩 추가한다.

- v0.2 변경: 텍스트 입력을 1순위로, 음성은 P2 보조로 변경 / 표현 정규화(R8) 추가 / 날씨 입력(P2)·날씨 자동 연동(P4) 추가
- v0.3 변경: 기술 스택 확정 / Vercel 배포를 필수로 변경하고 셋업 단계에서 먼저 배포 / 요청 횟수 제한 등 비용 방어(R9) 추가 / 일정 재배치(셋업 미착수 기준)
- v0.4 변경: 사진·서류 첨부를 P2로 내림 / 데모 데이터를 P1(R10)으로 올림 / 모호한 입력은 칩에서 수정(채팅으로 칩 고치기는 P2) / 시간대·날짜 경계 규칙(R2) / 에피소드 닫기 규칙(R1) / 사전 우선 파싱으로 LLM 호출 생략(R1) / 질문 분류와 위험 키워드 강제 판정(R4) / 체중 미입력 시 판정(R6) / 모델 확정(ADR-0001) / 셋업 완료 반영
- v0.5 변경: 화면 구조 신설(R0: 하단 탭 없음, 메인 = 기록 목록, 입력창 → 채팅) / 채팅 하나에서 기록·상담을 앱이 나눔, 애매하면 기록(R1) / 칩 즉시 저장 + 되돌리기(R1) / "조용한 기록"을 "짧은 기록 응답 + 위험 상황 예외"로(R3) / 근거 기록 카드는 코드가 만듦, 기록+상담 응답 순서(R4) / 기록 경로 위험 안내와 등급 × 모드 고정 문장(R6) / 데이터 모델 추가(R7)
- 2026-10-30 문서 구조: 요구사항을 영역별 파일(`docs/prd/`)로 나누고 변경 내역·열린 질문·지표(`docs/metrics.md`)를 분리. 날짜별 일정은 `docs/PLAN.md`로 일원화. Goals의 수치는 지표 ID로 가리킴. 요구사항 내용은 바꾸지 않음.
- 2026-10-30 기술 스택: 상태 관리에서 "필요 시 Zustand"를 빼고 전역 상태 라이브러리를 쓰지 않는다로 정함 (ADR-0003).
- 2026-10-30 기술 스택: 자동 검사(husky + GitHub Actions) 행 추가 (ADR-0005).
- 2026-10-30 문서 구조: 5장(마감과 자르는 순서)을 없앰. 우선순위와 자르는 순서는 개인 계획(`docs/plan.md`)에서 관리. Success Metrics는 5장으로. 요구사항 내용은 바꾸지 않음.
- 2026-11-01 R1·R11: 기록은 기록 메시지에서만 만들고 이전 대화는 LLM에 넣지 않음(R1) / 기록 종류와 항목을 R11로 분리, 종류·항목·값 목록은 나중에 사용자가 고칠 수 있는 설정으로 다루고 이번에는 기본값만(R11) / 기록 종류 편집을 P2 "나중에"에 추가.
- 2026-11-01 R1: 의도 나누기에서 코드는 확실한 경우(문장 끝 질문, 인사만, 칩이 다 채워짐)만 정하고 나머지는 파싱용 모델이 고름 / 인사가 섞이면 나머지 내용으로 나눔 / 인사만 있으면 고정 문장 두 채팅 / 의도 테스트 수락 기준 추가.
- 2026-11-01 R4: "조회" 질문은 상담 모델 없이 근거 카드와 고정 문장으로 답하는 방향을 적음(R4 계획 때 구체화).
- 2026-11-01 R1: 에피소드는 열 때부터 기록, 진행 중 띠는 최대 2줄 + [종료] 버튼, 열린 에피소드는 기록 목록에도 "진행 중"으로 보임 / 띠 슬라이드를 P2 "나중에"에 추가. R11 열린 질문 2개 추가.
- 2026-11-01 R1: 기준 시간이 지난 열린 에피소드는 지속시간 "모름"으로 자동 종료하고 고정 문장으로 안내.
- 2026-11-01 R1: 의도를 정하지 못했는데 LLM이 실패하면 메모 기록으로 원문 저장 후 안내.
- 2026-11-01 R1·R12: 에피소드 열기·닫기·진행 중 띠·자동 종료를 R1에서 R12로 분리.
- 2026-11-01 R1: 하위 요구사항(R1-1~R1-12)에 번호를 붙이고 수락 기준을 그 아래로 옮김(R1-k.m). 기존 문장은 모두 유지. 수락 기준 추가: 입력 수단(R1-1.1), 의도 미정 + LLM 실패 시 메모(R1-5.2), 빈 칸 안내(R1-7.1), 한 문장 여러 기록(R1-8.1).
- 2026-11-01 R2·R8: R1이 최소 시각 파서·사전으로 먼저 동작하므로, R2·R8 완료 후 R1 수락 기준 테스트를 다시 통과시키는 수락 기준 추가.
- 2026-11-01 문서 구조: PRD를 R마다 파일 하나(`docs/prd/R<n>.md`)로 나누고, 사용자 스토리·"나중에"·기술 스택을 관련 R 파일로 옮김. R1의 열린 질문 칸을 "비블로킹"으로(음성 입력 질문). 요구사항 내용은 바꾸지 않음 (ADR-0011).
