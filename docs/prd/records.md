# 기록

> 상위: `docs/PRD.md` / 자주 함께 보는 R: R6(위험 기록 안내), R7(데이터 모델)

## 사용자 스토리

- 보호자로서, "방금 배변했는데 무른 편이야"처럼 한 문장을 입력해 기록하고 싶다. 타이핑만으로 빠르게 남기기 위해서다.
- 보호자로서, "무른 편", "응아가 흐물흐물해", "물렁해"처럼 같은 상태를 다르게 말해도 같은 칩으로 분류되길 원한다. 집계와 상담 결과가 표현에 따라 흔들리지 않게 하기 위해서다.
- 보호자로서, "방금", "10분 전", "어제 저녁쯤" 같은 표현이 실제 시각으로 변환되길 원한다. 시각을 직접 입력하는 수고를 줄이기 위해서다.
- 보호자로서, 저장된 요약 칩("발작 · 방금 · 약 2분")을 보고 틀린 칸만 바로 고치거나 되돌리고 싶다. AI의 해석 오류가 그대로 남지 않게 하기 위해서다.
- 보호자로서, 발작·절뚝임·천둥 떨림처럼 시작과 끝이 있는 일을 하나의 에피소드로 열어두고 나중에 지속시간·강도를 붙이고 싶다. 반복되는 증상의 경과를 추적하기 위해서다.
- 보호자로서, 기록할 때는 짧은 확인만 받고 싶다. 판단은 내가 물을 때 받고 싶다. 단, 초콜릿을 먹은 것처럼 위험한 일은 묻지 않아도 알려주길 원한다.
- (예외) 입력이 모호하면(양, 종류, 시각 불명) 칩의 해당 칸에 `?` 표시와 후보를 보여주고, 탭해서 고르거나 직접 수정하게 한다.
- (빈 상태) 기록이 없을 때는 첫 기록 예시 문장을 보여준다.
- (P2) 보호자로서, 칩을 탭하는 대신 "아니 30분 전이야"처럼 채팅으로 말해 칩을 고치고 싶다.
- (P2) 보호자로서, 사진과 병원 검사 서류를 기록에 첨부하고 싶다. 병원에서 다시 보여주기 위해서다.
- (P2) 보호자로서, 산책 중 손이 바쁠 때 음성으로 기록하고 싶다.
- (P2) 보호자로서, 그날 날씨를 기록에 남기고 싶다. 천둥 떨림이나 비 오는 날의 컨디션을 나중에 함께 보기 위해서다.

## 요구사항 (P1)

**R1. 채팅 입력: 기록과 상담 나누기, 기록 저장**
- 텍스트 채팅 입력이 1순위 입력이다. (음성은 P2)
- **메시지 의도 나누기**: 메시지 하나를 `기록` / `상담` / `기록+상담` / `기타(인사 등)` 중 하나로 나눈다.
  - ① 코드가 먼저 판단한다: 질문 신호("?", "왜", "어때", "괜찮아", "보여줘", "알려줘", "어땠어" 등)가 있으면 상담, 기록 종류 키워드가 있으면 기록, 둘 다 있으면 기록+상담.
  - ② 코드로 판단이 안 되면 LLM(파싱용 모델)이 값 목록 안에서 고른다.
  - ③ **그래도 애매하면 기록으로 본다.** 칩을 보고 사용자가 고치면 된다.
- **기록 처리 순서**: ① 키워드 사전(R8)과 시각 파서(R2)로 먼저 채운다 → ② 종류·핵심 값이 모두 채워지면 **LLM을 호출하지 않는다** → ③ 빈 칸이 남을 때만 LLM이 Zod 스키마로 검증된 구조화 출력을 낸다. 비용과 요청 제한 소모를 줄이기 위해서다.
- **바로 저장**: 칩은 만들어지는 즉시 저장된다. 저장 버튼은 없다. 칩 카드에는 "되돌리기"가 있고, 칸을 탭해 고칠 수 있다. 고치지 않으면 그대로 기록이다.
- **기록 응답 문장은 코드의 고정 문장**이다(LLM을 쓰지 않음). 형식: 무엇을 기록했는지 + 비어 있는 칸이 있으면 무엇을 더 알려주면 좋은지. 예: "초코의 배변을 기록했어요. 상태(무른지, 딱딱한지)를 알려주시면 더 정확해요."
- 기록 종류: 순간 기록(배변 상태·횟수, 식사, 간식, 산책과 산책 중 좋았던 일, 주워 먹은 것, 메모), 에피소드 기록(절뚝임, 발작, 천둥 떨림: 시작 시각·지속시간·강도·열림/닫힘). 값 목록은 `values.ts`의 `ENTRY_KINDS`.
- 한 문장에 기록이 여러 개 있으면("밥 먹고 산책했어") 칩 카드를 여러 장 만든다.
- 모호한 칸은 `?` 표시와 후보 칩으로 보여주고 탭해서 고른다. 채팅으로 칩 고치기는 P2다. **예외**: 바로 앞 응답이 위험 기록의 정보(양·종류)를 물었다면, 다음 메시지의 양·종류는 새 기록이 아니라 그 기록에 붙이고 다시 판정한다(R6).
- 강아지 이름은 기록 내용으로 보지 않는다. 예: 이름이 "초코"이면 "초코가 초코 먹었어"의 앞 "초코"는 강아지, 뒤 "초코"는 음식이다.
- 에피소드 닫기: "끝났어", "멈췄어" 같은 종료 표현은 ① 종류가 있으면 그 종류 중 가장 최근에 열린 에피소드를 닫고, ② 종류가 없으면 열린 에피소드가 하나일 때만 그것을 닫는다. ③ 열린 에피소드가 여럿이거나 없으면 칩에서 고르게 한다. 지속시간 표현("2분쯤")은 `durationSec`에 넣고, 종료 시각은 시작 시각 + 지속시간으로 계산한다(없으면 입력 시각).
- 열린 에피소드는 메인 위쪽 "진행 중" 띠로 보여주고, 탭해서 닫을 수 있다.
- 수락 기준
  - [ ] "방금 배변했는데 무른 편" 입력 시 현재 시각, 배변, 무름으로 칩이 저장되고 확인 문장이 나온다. (사전으로 모두 채워지므로 LLM 호출 없음)
  - [ ] "발작했어"로 에피소드가 열리고, 이후 "끝났어, 2분쯤"이 같은 에피소드에 지속시간을 붙인다.
  - [ ] 칩에서 시각·값을 고치면 저장된 기록이 바뀌고, "되돌리기"로 기록을 취소할 수 있다.
  - [ ] "지난주 배변 어땠어?"는 기록을 만들지 않고 상담으로 처리된다.
  - [ ] "오늘 설사했는데 왜 그럴까?"는 설사 칩 저장과 상담 답변이 함께 나온다.
  - [ ] "초코가 초코 먹었어"(이름 초코)는 주워 먹은 것 · 초콜릿으로 기록된다.
  - [ ] LLM 호출이 실패하거나 한도를 초과해도, 사전으로 채운 칩과 원문으로 저장된다.

**R2. 시각 처리**
- "방금/지금/N분 전/아까/어제 저녁쯤" 등을 기기 현재 시각 기준으로 변환한다. 규칙 기반 파서가 먼저, 모호한 경우만 LLM 보조.
- 시각 표현이 없으면 입력 시각으로 둔다.
- **시간대 규칙**: 저장은 UTC ISO 문자열이다. 사람의 날짜 개념("어제", "오늘", "지난주", 일별 집계의 하루)은 **기기 현지 시간대** 기준으로 계산한 뒤 UTC로 바꿔 조회한다. 파서와 집계 함수는 "현재 시각"과 "시간대"를 인자로 받아 테스트에서 고정할 수 있게 한다.
- 대략적인 표현의 기준 시각: 아침 08:00, 점심 12:00, 오후 15:00, 저녁 19:00, 밤 22:00, 새벽 03:00, 아까 30분 전. 이렇게 추정한 시각은 칩에 "추정"으로 표시한다.
- 수락 기준
  - [ ] "방금"은 현재 시각으로 저장된다.
  - [ ] "10분 전"은 현재 시각 10분 전으로 저장된다.
  - [ ] 모호한 표현은 추정 시각을 칩에 보여주고 수정할 수 있다.
  - [ ] KST 00:30에 입력한 "어제 저녁"은 KST 기준 전날 19:00이 된다. (UTC 날짜와 현지 날짜가 다른 경우의 테스트)

**R3. 짧은 기록 응답**
- 기록만 한 메시지에는 기록 확인과 더 알려줄 정보만 답한다. 원인 추측, 관찰 안내, 병원 권유는 하지 않는다. 판단은 사용자가 물을 때(상담) 한다.
- **예외: 위험 상황.** 기록 내용이 `assess()`의 위험 규칙(위험 음식, 5분 넘는 발작 등)에 걸리면, 확인 문장 아래에 등급별 안내를 붙인다(R6). 기록과 상담이 한 채팅에 있어 사용자가 답을 기대할 수 있고, 위험 상황은 시간이 중요하기 때문이다.
- 수락 기준
  - [ ] "무른 변 봤어", "2분 발작했어"에는 확인 문장만 나오고 병원 권유가 없다.
  - [ ] "초콜릿 먹었어"에는 확인 문장 + 등급 안내 + 양·종류 질문이 나온다.

**R8. 표현 정규화 (같은 의미 → 같은 칩 값)**
- 칩에 들어가는 값은 코드에 고정한 **값 목록(enum)**에서만 고른다. 예: 배변 상태 `딱딱함 / 정상 / 무름 / 설사 / 혈변·점액 / 기타`, 강도 `약 / 중 / 강`, 기록 종류 등. 값 목록은 한 파일에 모아 Zod 스키마, 칩 UI, 집계 함수가 모두 같은 목록을 참조한다.
- 처리 순서: ① 키워드 사전으로 먼저 분류(예: "응가/응아/똥/변", "무른/물렁/흐물") → ② 사전으로 안 잡히면 LLM이 값 목록 중에서 선택(스키마가 목록 밖 값을 허용하지 않음) → ③ 확신이 낮으면 칩에 후보를 함께 보여주고 사용자가 탭해서 고름 → ④ 어디에도 맞지 않으면 `기타`로 두고 원문을 보존.
- 원문 문장은 정규화된 값과 함께 항상 저장한다. 분류 기준을 개선하면 원문으로 재분류할 수 있다.
- 수락 기준
  - [ ] "무른 편", "응아가 흐물흐물해", "물렁해"가 모두 `무름` 칩이 된다.
  - [ ] "딱딱해", "토끼똥 같아"는 `딱딱함`으로 분류되어 `무름`과 구분된다.
  - [ ] 확신이 낮은 입력은 후보 칩이 함께 표시되고 탭으로 수정할 수 있다.
  - [ ] 목록에 없는 표현은 `기타`로 저장되고 원문이 남는다.
  - [ ] 같은 의미의 다른 표현 20~30개와 기대 값을 비교하는 **표현 사전 테스트**가 자동으로 통과한다.

## 나중에

- (P2) **채팅으로 칩 고치기**: 직전 칩에 대해 "아니 30분 전이야", "설사였어"처럼 입력하면 새 기록이 아니라 그 칩을 고친다. 칩 탭 수정과 함께 쓴다. (위험 기록의 양·종류 보충은 P1 예외로 먼저 만든다, R1)
- (P2) **사진·서류 첨부**: 기록에 사진과 병원 검사 서류를 첨부하고 메인 기록 목록에서 본다. IndexedDB에 저장하며 AI가 해석하지 않는다. 데이터 모델의 `attachmentIds`는 P1부터 비어 있는 필드로 둔다.
- (P2) **빠른 버튼**: 배변(상태 선택), 산책 시작/종료, 절뚝임·발작 타이머, 천둥 떨림 강도 탭. 한 손 사용을 위한 보조 입력.
- (P2) **음성 입력**: 브라우저 음성 인식(Web Speech API, Chrome 기준)으로 말한 내용을 텍스트로 변환해 같은 입력 파이프라인(R1, R2, R8)에 넣는다. 추후 앱 출시 시 1순위로 승격 가능.
- (P2) **날씨 수동 입력**: 기록의 부가 필드. 값 목록 `맑음 / 흐림 / 비 / 눈 / 천둥·번개 / 폭염 / 한파`. "천둥 쳐서 덜덜 떨어" 같은 문장에서 날씨와 행동을 함께 추출해 한 칩에 표시한다. 일별 요약에 날씨 한 줄을 추가해 상담에서 날씨와 기록을 함께 근거로 쓸 수 있게 한다. (R8과 같은 정규화 방식 사용)
- (P3) **일기 기록 입력**: 별도 화면 없이 채팅으로 "일기" 종류를 기록 (발작 기록과 같은 방식).
- (P4) **날씨 자동 연동**: 기록 시각과 위치로 기상 API에서 날씨를 자동으로 붙인다. 위치 권한, 외부 API 키, 호출 한도 확인 필요 (API는 착수 시 조사).
