# R0. 화면 구조

> 색인: `docs/PRD.md` / 자주 함께 보는 R: R1, R4, R10

## 사용자 스토리

- (빈 상태) 기록이 없을 때는 첫 기록 예시 문장을 보여준다.
- 보호자로서, 앱을 열면 지금까지 남긴 기록이 날짜별로 먼저 보이길 원한다.
- 보호자로서, 기록할지 물어볼지 고르지 않고 입력창 하나에 그냥 적고 싶다. 앱이 알아서 기록하거나 답해 주길 원한다.

## 요구사항 (P1)

- **R0-1 화면 구성**: 하단 탭은 없다. 화면은 메인 하나와 설정이다. 설정: 프로필, 상담 태도(모드), 데모 데이터(R10), 면책 안내. 메인·설정·채팅은 헤더와 본문으로 나뉘고, 헤더는 화면 위에 고정된다. 스크롤은 본문에만 생긴다. 메인의 하단 입력창도 본문 밖 아래에 고정된다.
  - 확인: R7(프로필), R5(모드), R10(데모 데이터)의 수락 기준
  - 수락 기준
    - [x] R0-1.1 메인(모바일·태블릿·PC 목록 칸)과 설정에서 본문을 끝까지 스크롤해도 헤더가 제자리에 있고, 문서 전체가 아니라 본문 영역만 스크롤된다. 모바일·태블릿 메인의 하단 입력창도 제자리에 있다.
- **R0-2 기록 목록**: 메인은 기록 목록이다. 저장된 기록을 현지 날짜별로, 날짜와 그날 기록 모두 오래된 것이 위(최신이 맨 아래, 입력창 바로 위)로 보여준다. 슬랙처럼 열 때부터 맨 아래가 보이고 위로 올리면 이전 기록이 보인다. 맨 위에서 아래로 내려가는 움직임이 보이지 않는다. 오른쪽 위에 설정 아이콘, 맨 아래에 입력창("기록하거나 물어보세요")이 있다. 열린 에피소드 "진행 중" 띠(R12)는 입력창이 있는 곳마다 그 바로 위에 있다: 모바일·태블릿 메인의 하단 입력창 위, 채팅을 열면 채팅 입력창 위, PC는 오른쪽 채팅 입력창 위. 메인의 기록을 탭하면 같은 칩 카드가 열려 수정·삭제할 수 있다.
  - 수락 기준
    - [ ] R0-2.1 첫 화면에서 기록 목록과 입력창이 보인다.
    - [ ] R0-2.2 메인을 열면 가장 최근 기록이 입력창 바로 위에 보이고, 위로 스크롤하면 이전 날짜가 나온다. 새 기록이 저장되면 맨 아래에 붙어 보인다.
    - [ ] R0-2.3 메인에서 기록을 탭해 고치거나 지울 수 있다.
    - [x] R0-2.4 열린 에피소드가 있으면 진행 중 띠가 모바일 메인의 하단 입력창 바로 위, 채팅 입력창 바로 위, PC 채팅 입력창 바로 위에 보인다.
- **R0-3 채팅**: 입력창을 누르면 채팅 화면이 아래에서 올라온다. 채팅 하나에서 기록과 상담을 모두 한다. 사용자가 고르지 않고 앱이 입력 내용을 보고 나눈다(R1). 모바일·태블릿에서 채팅 화면은 화면 전체(100%)를 덮고, 열려 있는 동안 뒤의 기록 목록은 스크롤되지 않는다. 채팅 대화는 저장되어 다시 열어도 보인다. 단, 새 메시지를 처리할 때 이전 대화를 LLM에 넣지 않는다(R4).
  - 수락 기준
    - [ ] R0-3.1 입력창을 누르면 채팅이 열린다.
    - [ ] R0-3.2 채팅을 닫았다 열어도 이전 대화가 남아 있다.
    - [ ] R0-3.3 모바일·태블릿에서 채팅이 화면 전체를 덮고, 채팅을 스크롤해도 뒤의 기록 목록은 움직이지 않는다.
- **R0-4 화면 폭 구간**: 모바일(767px 이하)·태블릿(768~1023px)·PC(1024px 이상)를 화면 폭으로만 나눈다. 기기 특성(터치, 입력 방식)은 보지 않는다.
  - 모바일·태블릿은 1단이다. 기록 목록이 화면 폭의 92%를 쓰고, 입력창을 누르면 위처럼 채팅이 올라온다. 태블릿에서도 목록이 화면을 넓게 쓴다.
  - PC는 2단이다. 왼쪽에 기록 목록, 오른쪽에 채팅을 나란히 두고 채팅은 늘 열려 있다. 2단 전체는 화면 폭의 92%, 최대 1200px이고 가운데 정렬한다. 채팅 칸은 2단 폭의 40%, 최대 420px다.
  - 설정 화면은 화면 폭의 92%, 최대 672px다.
  - 수락 기준
    - [x] R0-4.1 1024px 이상에서는 기록 목록과 채팅이 나란히 보이고, 채팅에서 저장·되돌리기한 기록이 목록에 바로 반영된다.
    - [x] R0-4.2 900px 창에서 기록 목록이 1단으로 화면 폭의 92%를 쓴다.
    - [x] R0-4.3 1920px 창에서 2단 전체가 1200px로 가운데에 놓이고 채팅 칸이 420px다.
- **R0-5 최소 폭**: 가장 좁은 화면은 320px이다. 320px부터 가로 스크롤 없이 쓸 수 있고, 그보다 좁으면(화면 분할 등) 레이아웃을 더 줄이지 않고 가로 스크롤이 생긴다.
  - 수락 기준
    - [x] R0-5.1 320px 폭에서 메인과 채팅에 가로 스크롤이 없고, 320px보다 좁으면 기록 목록이 320px 폭을 유지한 채 가로 스크롤된다.
- **R0-6 데이터 상태**: 기록 목록과 채팅은 데이터를 불러올 때 로딩 / 데이터 없음 / 오류 / 데이터 네 상태로 나눠 보여준다. 데이터를 불러오는 동안에는 로딩을 띄운다.
  - 로딩: 기록 목록은 기록 줄 모양의 회색 자리 3줄, 채팅은 말풍선 모양 회색 자리 2개
  - 데이터 없음: 기록 목록은 "아직 기록이 없어요"와 첫 기록 예시 문장, "샘플 기록 불러오기" 버튼. 채팅은 인사 고정 문장(R1-3의 두 채팅)을 화면에만 보여주고 대화로 저장하지 않는다.
  - 오류: 기록 목록은 "기록을 불러오지 못했어요", 채팅은 "대화를 불러오지 못했어요"와 함께 "다시 시도" 버튼. 누르면 다시 불러온다.
  - 수락 기준
    - [ ] R0-6.1 기록 목록과 채팅을 불러오는 동안 회색 자리가 보이고, 다 불러오면 데이터로 바뀐다.
    - [ ] R0-6.2 기록이 없으면 예시 문장과 "샘플 기록 불러오기"가, 대화가 없으면 인사 문장이 보인다. 인사 문장은 새로고침 후 대화 기록에 남지 않는다.
    - [ ] R0-6.3 불러오기에 실패하면 오류 문장과 "다시 시도"가 보이고, 누르면 다시 불러온다.
- **R0-7 오버레이 스크롤바**: 모든 스크롤 영역(메인, 설정, PC 목록 칸과 채팅 칸, 채팅·칩 수정 시트)에서 기본 스크롤바는 숨기고, 폭을 차지하지 않는 얇은 막대를 내용 위 오른쪽 끝에 겹쳐 보여준다. 막대는 스크롤하는 동안이나 마우스를 올렸을 때 보이고, 멈추고 1초 뒤 서서히 사라진다. 막대 길이와 위치는 보이는 비율과 스크롤 위치를 따르고, 마우스로 끌면 스크롤된다. 빈 홈 클릭은 하지 않는다. 휠·터치·키보드 스크롤은 브라우저 기본 그대로다. 내용이 짧아 스크롤이 없으면 막대를 그리지 않는다.
  - 수락 기준
    - [ ] R0-7.1 스크롤바가 항상 보이는 환경(Windows Chrome 등)에서도 스크롤이 생길 때 내용 폭이 줄거나 밀리지 않는다.
    - [ ] R0-7.2 스크롤하거나 마우스를 올리면 막대가 보이고, 멈추고 1초 뒤 사라진다. 스크롤이 없으면 막대가 없다.
    - [ ] R0-7.3 막대를 마우스로 끌면 그만큼 스크롤된다.

## 나중에

- **가상 스크롤**: 기록이 수천 건으로 쌓이면 기록 목록을 보이는 부분만 그리고, 위로 올릴 때 이전 기록을 이어 불러온다. 화면이 튀지 않고 맨 아래에서 시작하는 동작(R0-2)은 그대로 둔다. (R0)
