## 1. Problem Statement

강아지를 키우는 사람은 배변, 산책, 이상 행동(절뚝임, 발작, 천둥 떨림) 같은 사소하지만 중요한 정보를 기억에 의존해 쌓아두고, 아프거나 결정이 필요한 순간에 "언제부터, 몇 번, 얼마나"를 정확히 떠올리지 못한다. 이 앱은 채팅(텍스트)으로 기록을 쉽게 남기게 하고, 쌓인 기록을 근거로 질문에 답하는 "보조 보호자" AI를 제공한다. 웹사이트에서는 텍스트 입력이 가장 익숙하므로 1순위로 하고, 산책 중처럼 손이 바쁜 상황을 위한 음성 입력은 보조로 둔다(추후 앱 출시 시 1순위로 올릴 수 있음).

**타깃 사용자**: 반려견 한 마리를 키우며 육아일기처럼 꾸준히 기록하고 싶은 보호자.

## 2. Goals

1. **빠른 기록**: 채팅 한 문장을 보내면 칩으로 바로 저장되고, 틀린 칸만 탭해서 고친다. (목표: 입력부터 저장까지 10초 내외)
2. **일관된 해석**: 같은 의미의 다른 표현("무른 편", "흐물흐물해")이 같은 칩 값으로 분류된다.
3. **근거 있는 상담**: 상담 답변은 저장된 기록을 근거로 하고, 어떤 기록을 몇 건 봤는지 표시한다.
4. **정확한 집계**: 횟수·분포·지속시간 같은 숫자는 코드가 계산하고 LLM은 해석과 문장화만 한다.
5. **일관된 안전 판단**: 고위험 상황은 모드(과보호/중립/무던)와 무관하게 같은 안내를 한다. (자체 평가 케이스 약 20개에서 모드 간 모순 0건)
6. **제출 가능한 데모**: 월요일 09:00까지 GitHub 저장소와 Vercel 배포 주소에서 실행 가능한 상태.

## 3. Non-Goals

- **로그인, 가족 공유**: 5일 일정에 과함. 단, 데이터를 `dogId` 기준으로 설계해 추후 초대 기반 접근을 붙일 수 있게 한다.
- **사진/검사 서류의 AI 해석**: 비용과 오판 위험. 사진·서류는 첨부와 보관만 한다.
- **진단, 처방, 투약량 안내**: 수의 행위 영역. 앱은 "병원 상담 권유"까지만 한다. 구토 유도 방법도 안내하지 않는다.
- **여러 마리 관리, 산책 매칭/로테이션**: 범위 밖. 한 마리 고정.
- **서버 저장, 기기 간 동기화**: 비용과 개인정보 부담. 브라우저 로컬 저장.

## 4. User Stories

### 화면
- 보호자로서, 앱을 열면 지금까지 남긴 기록이 날짜별로 먼저 보이길 원한다.
- 보호자로서, 기록할지 물어볼지 고르지 않고 입력창 하나에 그냥 적고 싶다. 앱이 알아서 기록하거나 답해 주길 원한다.

### 기록
- 보호자로서, "방금 배변했는데 무른 편이야"처럼 한 문장을 입력해 기록하고 싶다. 타이핑만으로 빠르게 남기기 위해서다.
- 보호자로서, "무른 편", "응아가 흐물흐물해", "물렁해"처럼 같은 상태를 다르게 말해도 같은 칩으로 분류되길 원한다. 집계와 상담 결과가 표현에 따라 흔들리지 않게 하기 위해서다.
- 보호자로서, "방금", "10분 전", "어제 저녁쯤" 같은 표현이 실제 시각으로 변환되길 원한다. 시각을 직접 입력하는 수고를 줄이기 위해서다.
- 보호자로서, 저장된 요약 칩("발작 · 방금 · 약 2분")을 보고 틀린 칸만 바로 고치거나 되돌리고 싶다. AI의 해석 오류가 그대로 남지 않게 하기 위해서다.
- 보호자로서, 발작·절뚝임·천둥 떨림처럼 시작과 끝이 있는 일을 하나의 에피소드로 열어두고 나중에 지속시간·강도를 붙이고 싶다. 반복되는 증상의 경과를 추적하기 위해서다.
- 보호자로서, 기록할 때는 짧은 확인만 받고 싶다. 판단은 내가 물을 때 받고 싶다. 단, 초콜릿을 먹은 것처럼 위험한 일은 묻지 않아도 알려주길 원한다.
- (예외) 입력이 모호하면(양, 종류, 시각 불명) 칩의 해당 칸에 `?` 표시와 후보를 보여주고, 탭해서 고르거나 직접 수정하게 한다.
- (빈 상태) 기록이 없을 때는 첫 기록 예시 문장을 보여준다.
- 심사자/방문자로서, 샘플 기록을 한 번에 불러와 앱의 기록 목록과 상담을 바로 체험하고 싶다.
- (P2) 보호자로서, 칩을 탭하는 대신 "아니 30분 전이야"처럼 채팅으로 말해 칩을 고치고 싶다.
- (P2) 보호자로서, 사진과 병원 검사 서류를 기록에 첨부하고 싶다. 병원에서 다시 보여주기 위해서다.
- (P2) 보호자로서, 산책 중 손이 바쁠 때 음성으로 기록하고 싶다.
- (P2) 보호자로서, 그날 날씨를 기록에 남기고 싶다. 천둥 떨림이나 비 오는 날의 컨디션을 나중에 함께 보기 위해서다.

### 상담
- 보호자로서, "지난주 배변 어땠어?", "발작 기록 모아서 보여줘"처럼 기록을 조회·요약하고 싶다. 병원에서 경과를 정확히 말하기 위해서다.
- 보호자로서, "오늘 설사했는데 왜 그럴까?"에 최근 식사·간식·주워 먹은 것을 근거로 한 원인 후보를 받고 싶다.
- 보호자로서, "초콜릿 먹었는데 괜찮아?"처럼 위험 상황에서 일관되고 안전한 안내를 받고 싶다.
- 보호자로서, 답변이 본 기록 범위를 알려주고, 원하면 더 넓은 기간으로 확장하고 싶다.

### 모드
- 보호자로서, 내 성향에 맞게 과보호/중립/무던 중 상담 태도를 고르고 싶다. 병원 권유 기준과 안내의 양이 내 불안 수준에 맞았으면 한다.

## 5. Requirements

### P1 (필수)

**R0. 화면 구조 (v0.5 신설)**
- **하단 탭은 없다.** 화면은 메인 하나와 설정이다.
- **메인 = 기록 목록**: 저장된 기록을 현지 날짜별로(최신이 위) 보여준다. 위쪽에 열린 에피소드 "진행 중" 띠, 오른쪽 위에 설정 아이콘, 맨 아래에 입력창("기록하거나 물어보세요")이 있다.
- **입력창을 누르면 채팅 화면**이 아래에서 올라온다. 채팅 하나에서 기록과 상담을 모두 한다. 사용자가 고르지 않고 앱이 입력 내용을 보고 나눈다(R1).
- 채팅 대화는 저장되어 다시 열어도 보인다. 단, 새 메시지를 처리할 때 이전 대화를 LLM에 넣지 않는다(R4).
- 메인의 기록을 탭하면 같은 칩 카드가 열려 수정·삭제할 수 있다.
- 설정: 프로필, 상담 태도(모드), 데모 데이터(R10), 면책 안내.
- 수락 기준
  - [ ] 첫 화면에서 기록 목록과 입력창이 보이고, 입력창을 누르면 채팅이 열린다.
  - [ ] 채팅을 닫았다 열어도 이전 대화가 남아 있다.
  - [ ] 메인에서 기록을 탭해 고치거나 지울 수 있다.

**R1. 채팅 입력: 기록과 상담 나누기, 기록 저장**
- 텍스트 채팅 입력이 1순위 입력이다. (음성은 P2)
- **메시지 의도 나누기**: 메시지 하나를 `기록` / `상담` / `기록+상담` / `기타(인사 등)` 중 하나로 나눈다.
  - ① 코드가 먼저 판단한다: 질문 신호("?", "왜", "어때", "괜찮아", "보여줘", "알려줘", "어땠어" 등)가 있으면 상담, 기록 종류 키워드가 있으면 기록, 둘 다 있으면 기록+상담.
  - ② 코드로 판단이 안 되면 LLM(파싱용 모델)이 값 목록 안에서 고른다.
  - ③ **그래도 애매하면 기록으로 본다.** 칩을 보고 사용자가 고치면 된다.
- **기록 처리 순서**: ① 키워드 사전(R8)과 시각 파서(R2)로 먼저 채운다 → ② 종류·핵심 값이 모두 채워지면 **LLM을 호출하지 않는다** → ③ 빈 칸이 남을 때만 LLM이 Zod 스키마로 검증된 구조화 출력을 낸다. 비용과 요청 제한 소모를 줄이기 위해서다.
- **바로 저장**: 칩은 만들어지는 즉시 저장된다. 저장 버튼은 없다. 칩 카드에는 "되돌리기"가 있고, 칸을 탭해 고칠 수 있다. 고치지 않으면 그대로 기록이다.
- **기록 응답 문장은 코드의 고정 문장**이다(LLM을 쓰지 않음). 형식: 무엇을 기록했는지 + 비어 있는 칸이 있으면 무엇을 더 알려주면 좋은지. 예: "초코의 배변을 기록했어요. 상태(무른지, 딱딱한지)를 알려주시면 더 정확해요."
- 기록 종류: 순간 기록(배변 상태·횟수, 식사, 간식, 산책과 산책 중 좋았던 일, 주워 먹은 것, 메모), 에피소드 기록(절뚝임, 발작, 천둥 떨림: 시작 시각·지속시간·강도·열림/닫힘). 값 목록은 `values.ts`의 `ENTRY_KINDS`.
- 한 문장에 기록이 여러 개 있으면("밥 먹고 산책했어") 칩 카드를 여러 장 만든다.
- 모호한 칸은 `?` 표시와 후보 칩으로 보여주고 탭해서 고른다. 채팅으로 칩 고치기는 P2다. **예외**: 바로 앞 응답이 위험 기록의 정보(양·종류)를 물었다면, 다음 메시지의 양·종류는 새 기록이 아니라 그 기록에 붙이고 다시 판정한다(R6).
- 강아지 이름은 기록 내용으로 보지 않는다. 예: 이름이 "초코"이면 "초코가 초코 먹었어"의 앞 "초코"는 강아지, 뒤 "초코"는 음식이다.
- 에피소드 닫기: "끝났어", "멈췄어" 같은 종료 표현은 ① 종류가 있으면 그 종류 중 가장 최근에 열린 에피소드를 닫고, ② 종류가 없으면 열린 에피소드가 하나일 때만 그것을 닫는다. ③ 열린 에피소드가 여럿이거나 없으면 칩에서 고르게 한다. 지속시간 표현("2분쯤")은 `durationSec`에 넣고, 종료 시각은 시작 시각 + 지속시간으로 계산한다(없으면 입력 시각).
- 열린 에피소드는 메인 위쪽 "진행 중" 띠로 보여주고, 탭해서 닫을 수 있다.
- 수락 기준
  - [ ] "방금 배변했는데 무른 편" 입력 시 현재 시각, 배변, 무름으로 칩이 저장되고 확인 문장이 나온다. (사전으로 모두 채워지므로 LLM 호출 없음)
  - [ ] "발작했어"로 에피소드가 열리고, 이후 "끝났어, 2분쯤"이 같은 에피소드에 지속시간을 붙인다.
  - [ ] 칩에서 시각·값을 고치면 저장된 기록이 바뀌고, "되돌리기"로 기록을 취소할 수 있다.
  - [ ] "지난주 배변 어땠어?"는 기록을 만들지 않고 상담으로 처리된다.
  - [ ] "오늘 설사했는데 왜 그럴까?"는 설사 칩 저장과 상담 답변이 함께 나온다.
  - [ ] "초코가 초코 먹었어"(이름 초코)는 주워 먹은 것 · 초콜릿으로 기록된다.
  - [ ] LLM 호출이 실패하거나 한도를 초과해도, 사전으로 채운 칩과 원문으로 저장된다.

**R2. 시각 처리**
- "방금/지금/N분 전/아까/어제 저녁쯤" 등을 기기 현재 시각 기준으로 변환한다. 규칙 기반 파서가 먼저, 모호한 경우만 LLM 보조.
- 시각 표현이 없으면 입력 시각으로 둔다.
- **시간대 규칙**: 저장은 UTC ISO 문자열이다. 사람의 날짜 개념("어제", "오늘", "지난주", 일별 집계의 하루)은 **기기 현지 시간대** 기준으로 계산한 뒤 UTC로 바꿔 조회한다. 파서와 집계 함수는 "현재 시각"과 "시간대"를 인자로 받아 테스트에서 고정할 수 있게 한다.
- 대략적인 표현의 기준 시각: 아침 08:00, 점심 12:00, 오후 15:00, 저녁 19:00, 밤 22:00, 새벽 03:00, 아까 30분 전. 이렇게 추정한 시각은 칩에 "추정"으로 표시한다.
- 수락 기준
  - [ ] "방금"은 현재 시각으로 저장된다.
  - [ ] "10분 전"은 현재 시각 10분 전으로 저장된다.
  - [ ] 모호한 표현은 추정 시각을 칩에 보여주고 수정할 수 있다.
  - [ ] KST 00:30에 입력한 "어제 저녁"은 KST 기준 전날 19:00이 된다. (UTC 날짜와 현지 날짜가 다른 경우의 테스트)

**R3. 짧은 기록 응답 (v0.5에서 "조용한 기록 화면"을 바꿈)**
- 기록만 한 메시지에는 기록 확인과 더 알려줄 정보만 답한다. 원인 추측, 관찰 안내, 병원 권유는 하지 않는다. 판단은 사용자가 물을 때(상담) 한다.
- **예외: 위험 상황.** 기록 내용이 `assess()`의 위험 규칙(위험 음식, 5분 넘는 발작 등)에 걸리면, 확인 문장 아래에 등급별 안내를 붙인다(R6). 기록과 상담이 한 채팅에 있어 사용자가 답을 기대할 수 있고, 위험 상황은 시간이 중요하기 때문이다.
- 수락 기준
  - [ ] "무른 변 봤어", "2분 발작했어"에는 확인 문장만 나오고 병원 권유가 없다.
  - [ ] "초콜릿 먹었어"에는 확인 문장 + 등급 안내 + 양·종류 질문이 나온다.

**R4. 상담 (조회·요약, 원인 추측, 상황 판단)**
- 질문 유형 비중: 조회·요약 > 원인 추측 > 상황 판단.
- 불러올 기록의 기본 범위는 질문 주제별 규칙표로 정한다 (예: 설사 → 최근 3일 식사·간식·주워 먹은 것·배변, 절뚝임 → 최근 14일 에피소드·산책).
- 사용자가 "더 예전 것도", "한 달 전부터"처럼 요청하면 범위를 확장한다. 기간 표현은 규칙으로 파싱한다.
- 집계는 코드가 하고, LLM에는 기본 범위는 원본에 가깝게, 확장 시에는 **일별 요약**(횟수, 상태 분포, 지속시간 합계)으로 넘긴다. 에피소드와 주워 먹은 것은 요약에 묻지 않고 원본 한 줄씩 포함한다.
- **근거 기록 카드는 코드가 만든다.** 답변 위에 "최근 3일 식사·간식·주워 먹은 것 7건"처럼 본 범위와 건수, 기록 목록을 카드로 보여준다. LLM은 이 카드를 근거로 해석 문장만 쓰고, 기록 목록을 다시 옮겨 쓰지 않는다. 카드의 기록을 탭하면 해당 기록 칩이 열린다. 카드 아래에 범위 확장 버튼을 붙인다.
- 기록이 부족하면 부족하다고 말하고 지어내지 않는다. 예: "최근 3일 식사 기록이 1건뿐이라 원인을 좁히기 어려워요."
- **기록+상담 메시지**("오늘 설사했는데 왜 그럴까?")의 응답 순서: ① 질문에 대한 상담 답변(근거 카드 + 해석) → ② "말씀하신 설사 증상은 아래처럼 기록했어요. 더 알려주실 게 있으면 말씀해 주시거나 칩에서 고쳐 주세요." + 칩 카드. 새 기록은 근거 범위에 포함한다.
- "조회" 질문에는 안내 없이 모아서 보여주고, "판단 요청" 질문에는 `assess()`를 거친다.
- 질문 분류: 질문 유형(조회 / 원인 추측 / 상황 판단)과 주제는 LLM이 값 목록 안에서 고른다. 단, **위험 키워드**(초콜릿, 포도, 건포도, 자일리톨, 마카다미아, 양파, 마늘, 발작 등)가 있으면 분류 결과와 무관하게 코드가 `assess()`를 거치게 한다. 안전 판단이 LLM 분류 실수에 좌우되지 않게 하기 위해서다.
- 상담은 질문 한 개에 답변 한 개다. 이전 대화는 화면에 남기지만 LLM 맥락에는 넣지 않는다. (비용과 근거 범위를 명확히 하기 위해)
- 수락 기준
  - [ ] "지난주 배변 어땠어?"의 횟수·상태 분포가 코드 집계와 일치한다.
  - [ ] "발작 기록 모아서 보여줘"가 에피소드 타임라인 카드로 나온다.
  - [ ] 확장 요청 시 범위가 넓어지고 표시된 건수가 바뀐다.
  - [ ] 기록에 없는 정보를 답변에 만들어 넣지 않는다.
  - [ ] 집계 함수는 단위 테스트를 가진다.

**R5. 모드 (과보호 / 중립 / 무던, 기본 중립)**
- 내용 차이는 **설정값(코드)**, 말투 차이는 **프롬프트**로 처리한다.

| | 과보호 | 중립 | 무던 |
|---|---|---|---|
| 병원 권유 기준 | 낮음 | 중간 | 높음 |
| 관찰 항목 | 많음 | 핵심 3개 | 핵심 1~2개 |
| 원인 후보 | 드문 원인까지 | 흔한 원인 + 주의 1개 | 흔한 원인 위주 |
| 말투 | 걱정스럽고 조심스럽게 | 차분하고 객관적으로 | 느긋하고 가볍게 |

- 구체적 기준값은 설정 파일로 분리하고, **수의학 자료로 출처 확인 후 확정**한다. Claude가 공개 수의학 자료(Merck Veterinary Manual, VCA 등)로 출처를 단 초안을 만들고, 본인이 검토해 확정한다. 출처는 `docs/research/`에 남긴다.
- 수락 기준
  - [ ] 같은 질문에 모드별로 권유 기준·관찰 항목 수·원인 후보 범위·말투가 달라진다.
  - [ ] 모드를 바꿔도 기록 조회 결과(숫자)는 동일하다.

**R6. 안전 판단 `assess()` (최소 범위)**
- LLM 문장 생성 전에 코드가 위험 등급을 결정한다: 🔴 고위험 / 🟡 경계 / 🟢 저위험. LLM은 등급에 맞춰 문장만 쓰고, 출력 검사에서 등급과 모순되는 표현(예: 🔴에 "괜찮아요")을 거른다.
- 🔴: 모든 모드가 동일하게 "지금 동물병원에 연락"을 안내한다. 🟡: 모드별로 다르되 모든 모드에 최소 "병원에 전화 상담"을 포함한다. 🟢: 모드는 말투와 관찰 안내에 영향을 주고, 관찰 기준(증상은 보통 6~12시간 뒤 나타날 수 있음)을 항상 안내한다.
- 앱은 구토 유도 방법이나 투약량을 안내하지 않는다. 대신 시간이 중요함을 알리고 병원 연락을 안내한다.
- v1 범위: 초콜릿 독성 계산(체중, 종류, 양)과 고정 응답 몇 가지(포도·건포도, 자일리톨, 마카다미아, 양파·마늘). 한국 중독 상담 연락처는 미확인이라 "가까운 24시간 동물병원"으로 안내한다.
- 정보가 부족하면 보수적으로 판정한다: 체중이 프로필에 없거나, 초콜릿 종류·양을 알 수 없으면 계산하지 않고 🔴로 판정하고, 무엇을 알면 더 정확해지는지 함께 안내한다. 사용자가 양·종류를 알려주거나 칩에서 고치면 다시 판정한다(등급이 내려갈 수 있음).
- `assess()`는 순수 함수다(입력: 기록 또는 질문에서 뽑은 사실 + 프로필 + 최근 에피소드, 출력: 등급과 이유 코드). 모드는 입력에 넣지 않는다.
- **두 경로에서 호출된다**: 상담 질문(R4)과 위험 규칙에 걸린 기록(R3 예외).
- **기록 경로와 고정 응답의 문장은 코드의 고정 문장**이다. 등급 × 모드별 문장 표를 코드에 두고, LLM을 쓰지 않는다. 모드 간 모순을 테스트로 확인하기 위해서다. LLM 문장(+ 출력 검사)은 상담의 자유 답변에만 쓴다.
- 등급 × 모드 문장 예시 (초콜릿 기록)

| 등급 | 과보호 | 중립 | 무던 |
|---|---|---|---|
| 🔴 (많이 먹음, 또는 양·종류·체중 모름) | 모든 모드 동일: "지금 가까운 동물병원(야간이면 24시간 병원)에 연락해 주세요. 시간이 중요해요." + 모를 때는 "어떤 초콜릿을 얼마나 먹었는지 알려주시면 위험도를 다시 계산해 드릴게요." | ← | ← |
| 🟡 | "빨리 병원에 전화해 상담받아 보세요." | "병원에 전화로 상담받아 보시길 권해요." | "다니시는 병원에 전화로 한번 물어보세요." |
| 🟢 | "지금은 위험 수치 아래예요. 그래도 6~12시간 동안 구토·설사·흥분이 있는지 지켜봐 주시고, 걱정되면 병원에 연락해 주세요." | "위험 수치 아래예요. 6~12시간 동안 구토·설사·흥분을 지켜봐 주세요." | "이 양이면 크게 위험하지 않을 수 있어요. 6~12시간 정도 지켜보시고, 다니시는 병원에 문의해 보시면 더 좋아요." |
- 면책 화면: 앱은 진단이 아니며 응급 시 병원에 연락하라고 안내한다.
- 수락 기준
  - [ ] 평가 케이스 약 20개(체중 × 종류 × 양 × 경과 시간)에서 세 모드 모두 🔴 케이스가 같은 결론을 낸다.
  - [ ] 🟡 케이스는 모든 모드에 병원 전화 상담 안내가 포함된다.
  - [ ] 🔴 응답에 안심 표현이 없고, 구토 유도·투약량 안내가 없다.
  - [ ] 발작 5분 초과 같은 에피소드 기반 고위험 규칙은 무던 모드에서도 동작한다.
  - [ ] 체중 미입력 상태의 초콜릿 질문은 🔴로 판정된다.
  - [ ] "초콜릿 먹었어"(양 모름) 기록은 무던 모드에서도 🔴 문장이 나오고, 이어서 양·종류를 알려주면 다시 판정된다.

**R7. 프로필, 저장, 기반**
- 강아지 프로필(이름, 나이, 체중, 특이사항)과 설정(모드)을 저장한다.
- 저장은 브라우저 로컬(IndexedDB)이며, `getDog / saveEntry / listEntries` 같은 저장소 인터페이스 뒤에 숨긴다. 데이터는 `dogId` 기준.
- 기록 데이터 모델에 `weather`를 비어 있는 선택 필드로 미리 포함한다. (입력·자동 연동은 P2·P4)
- v0.5 데이터 모델 추가: 기록에 `timeEstimated`(시각을 추정했는지), `isDemo`(샘플 기록인지), 위험 음식 칸(음식 값 목록, 초콜릿 종류, 양 g). 상담 메시지는 **채팅 메시지**로 넓혀 기록과 상담을 함께 담고, 연결된 기록 id·근거 카드·위험 등급을 저장한다.
- LLM 호출은 서버 API Route에서만 한다 (API 키는 브라우저에 노출하지 않음).
- 모바일 우선 반응형. 화면 구조는 R0.
- 수락 기준
  - [ ] 새로고침 후에도 프로필과 기록이 유지된다.
  - [ ] 저장소 구현을 교체해도 화면 코드는 바뀌지 않는다.
  - [ ] `weather` 필드가 비어 있어도 모든 화면과 집계가 정상 동작한다.

**R8. 표현 정규화 (같은 의미 → 같은 칩 값)**
- 칩에 들어가는 값은 코드에 고정한 **값 목록(enum)**에서만 고른다. 예: 배변 상태 `딱딱함 / 정상 / 무름 / 설사 / 혈변·점액 / 기타`, 강도 `약 / 중 / 강`, 기록 종류 등. 값 목록은 한 파일에 모아 Zod 스키마, 칩 UI, 집계 함수가 모두 같은 목록을 참조한다.
- 처리 순서: ① 키워드 사전으로 먼저 분류(예: "응가/응아/똥/변", "무른/물렁/흐물") → ② 사전으로 안 잡히면 LLM이 값 목록 중에서 선택(스키마가 목록 밖 값을 허용하지 않음) → ③ 확신이 낮으면 칩에 후보를 함께 보여주고 사용자가 탭해서 고름 → ④ 어디에도 맞지 않으면 `기타`로 두고 원문을 보존.
- 원문 문장은 정규화된 값과 함께 항상 저장한다. 분류 기준을 개선하면 원문으로 재분류할 수 있다.
- 수락 기준
  - [ ] "무른 편", "응아가 흐물흐물해", "물렁해"가 모두 `무름` 칩이 된다.
  - [ ] "딱딱해", "토끼똥 같아"는 `딱딱함`으로 분류되어 `무름`과 구분된다.
  - [ ] 확신이 낮은 입력은 후보 칩이 함께 표시되고 탭으로 수정할 수 있다.
  - [ ] 목록에 없는 표현은 `기타`로 저장되고 원문이 남는다.
  - [ ] 같은 의미의 다른 표현 20~30개와 기대 값을 비교하는 **표현 사전 테스트**가 자동으로 통과한다.

**R9. 배포와 비용 방어 (Vercel)**
- 배포 주소는 제출 필수 항목이다. **셋업 단계에서 "빈 화면 + LLM 호출 1개" 상태로 먼저 Vercel에 배포**하고, 이후 GitHub 푸시마다 자동 배포되게 해서 마지막 날 배포 사고를 막는다.
- OpenAI API 키는 Vercel 환경변수로만 관리한다. 코드와 GitHub 저장소에는 올리지 않고, `.env*` 파일이 `.gitignore`에 포함되어 있는지 셋업 시 확인한다.
- **요청 횟수 제한(필수)**: LLM을 호출하는 모든 API Route는 `guardLlmRequest`를 통과한다. 기본값은 IP당 하루 30회, 서버 전체 하루 500회, 입력 500자이며 환경변수로 바꿀 수 있다. 한도 초과 시 사용자에게 이해하기 쉬운 안내 문구를 보여준다.
- 한계: 횟수는 서버 메모리에 저장되므로 Vercel에서는 인스턴스마다 따로 세고 재시작 시 초기화된다. 그래서 실제 지출 상한은 선불 크레딧과 OpenAI 프로젝트 한도가 맡고, 메모리 제한은 1차 방어로 둔다. 외부 저장소(Redis 등) 도입은 남용이 관찰되면 검토한다.
- OpenAI는 충전식(선불) 크레딧으로 사용해 지출 상한을 갖는다. 사용 한도 설정은 보조 안전장치로 확인한다.
- (선택) 심사자용 접근 코드.
- 수락 기준
  - [ ] Vercel 배포 주소에서 기록 입력과 상담이 동작한다.
  - [ ] GitHub 저장소 전체에 API 키가 포함되어 있지 않다.
  - [ ] 한도를 초과한 요청은 LLM을 호출하지 않고 안내 문구를 반환한다.
  - [ ] 너무 긴 입력은 LLM 호출 전에 거부된다.

**R10. 데모 데이터 (v0.4에서 P2 → P1)**
- 설정 화면의 "샘플 기록 불러오기" 버튼으로 약 2주치 샘플 기록(배변, 식사·간식, 산책, 주워 먹은 것, 발작·절뚝임·천둥 떨림 에피소드)을 넣는다. 심사자가 배포 주소를 처음 열었을 때와 시연 영상 촬영용이다.
- 샘플 기록의 시각은 불러오는 순간을 기준으로 상대 시각으로 만든다(항상 "최근 2주"가 되게).
- 샘플 기록은 `isDemo` 표시를 붙여 한 번에 지울 수 있다. 기록이 비어 있을 때 메인의 빈 상태 화면에서도 버튼을 보여준다.
- 수락 기준
  - [ ] 빈 상태에서 버튼 한 번으로 메인 기록 목록과 상담("지난주 배변 어땠어?", "발작 기록 모아서 보여줘")을 바로 체험할 수 있다.
  - [ ] 샘플 기록만 지우는 기능이 사용자가 직접 남긴 기록은 지우지 않는다.

### P2

- **채팅으로 칩 고치기**: 직전 칩에 대해 "아니 30분 전이야", "설사였어"처럼 입력하면 새 기록이 아니라 그 칩을 고친다. 칩 탭 수정과 함께 쓴다. (위험 기록의 양·종류 보충은 P1 예외로 먼저 만든다, R1)
- **사진·서류 첨부** (v0.4에서 P1 → P2): 기록에 사진과 병원 검사 서류를 첨부하고 메인 기록 목록에서 본다. IndexedDB에 저장하며 AI가 해석하지 않는다. 데이터 모델의 `attachmentIds`는 P1부터 비어 있는 필드로 둔다.
- **빠른 버튼**: 배변(상태 선택), 산책 시작/종료, 절뚝임·발작 타이머, 천둥 떨림 강도 탭. 한 손 사용을 위한 보조 입력.
- **음성 입력**: 브라우저 음성 인식(Web Speech API, Chrome 기준)으로 말한 내용을 텍스트로 변환해 같은 입력 파이프라인(R1, R2, R8)에 넣는다. 추후 앱 출시 시 1순위로 승격 가능.
- **일별 요약 단계 구분**: 최근 며칠은 원본, 이후는 일별 요약, 더 오래되면 주별 요약으로 계층화한다. (P1의 "일별 요약 한 단계"를 확장)
- **날씨 수동 입력**: 기록의 부가 필드. 값 목록 `맑음 / 흐림 / 비 / 눈 / 천둥·번개 / 폭염 / 한파`. "천둥 쳐서 덜덜 떨어" 같은 문장에서 날씨와 행동을 함께 추출해 한 칩에 표시한다. 일별 요약에 날씨 한 줄을 추가해 상담에서 날씨와 기록을 함께 근거로 쓸 수 있게 한다. (R8과 같은 정규화 방식 사용)

### P3

- **하루·주간 리포트**: 기록에서 AI가 일기·주간 회고를 생성하고 해당 날짜 사진을 함께 표시.
- **일기 기록 입력**: 별도 화면 없이 채팅으로 "일기" 종류를 기록 (발작 기록과 같은 방식).
- **웹 검색 연동**: 위험 상황 답변에 최신 검색 반영. 허용 출처 목록, 출처 표시, 검색 결과는 등급을 올리기만 하고 내리지 않음, 실패 시 고정 응답.
- 병원 제출용 요약 내보내기, 로그인 + 초대 기반 한 마리 접근, 기기 간 동기화, 모바일 앱 출시.

### P4

- **날씨 자동 연동**: 기록 시각과 위치로 기상 API에서 날씨를 자동으로 붙인다. 위치 권한, 외부 API 키, 호출 한도 확인 필요 (API는 착수 시 조사).

## 6. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript | API Route로 LLM 키를 서버에 숨김 |
| 스타일 | Tailwind | 모바일 우선 |
| 스키마/값 목록 | Zod | LLM 출력 검증, 칩 UI, 집계가 같은 값 목록을 참조 |
| LLM | OpenAI SDK (구조화 출력) | 파싱 `gpt-6-luna`(추론 none), 상담 `gpt-6.1-terra`(추론 low). 근거는 `docs/adr/0001-llm-model-selection.md`. 모델명은 환경변수로만 지정 |
| 로컬 저장 | IndexedDB (Dexie 등 얇은 래퍼) | 저장소 인터페이스 뒤에 숨김 |
| 상태 관리 | React 기본 상태, 필요 시 Zustand | |
| 테스트 | Vitest | 집계, 시각 파서, 표현 사전, 안전 평가 케이스 |
| 배포 | Vercel + GitHub 연동 | R9 참고 |

- GraphQL/Apollo는 사용하지 않는다(서버 데이터 없음, Route Handler로 충분).
- 확장 고려(로그인, 앱 출시): 저장소 인터페이스, `dogId` 기준 데이터 모델, 서버 API Route 분리로 이후 서버 저장·인증·앱 클라이언트를 붙일 수 있게 해둔다. 구체적인 방식은 확장 시점에 결정한다.
