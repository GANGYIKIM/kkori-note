# 지표

지표 정의는 이 표 한 곳에만 둔다. 다른 문서(PRD Goals, dev-log, ADR)는 ID만 적는다. 측정값은 `docs/metrics.csv`에 쌓이고 문서에 손으로 옮겨 적지 않는다.

## 선행 지표 (데모/자체 평가 기준)

| ID | 지표 | 목표 | 측정 | 관련 R | 상태 |
|---|---|---|---|---|---|
| M1 | 표현 사전 테스트(같은 의미 다른 표현 20~30개) 통과율 | 첫 실행 결과를 보고 확정 | 자동 (`npm run metrics`) | R8 | 사용 중 |
| M2 | 안전 평가 케이스(약 20건)의 모드 간 모순 | 0건 | 자동 (`npm run metrics`) | R6 | 사용 중 |
| M3 | 상담 답변 중 기록 근거를 1건 이상 인용한 비율 | 80% 이상 (제안) | LLM 포함, 측정 방법은 R4 구현 때 정함 | R4 | 사용 중 |
| M4 | 입력부터 저장까지 걸린 시간 | 약 10초 이내 | 시연 중 수동 측정 | R1 | 사용 중 |
| M5 | 저장된 칩 중 사용자가 고치거나 되돌린 비율 (사전만 / 사전+LLM으로 나눠 봄) | 첫 측정 결과를 보고 확정 | 로컬 기록, 마감 후 구현 | R1, R8 | 정의만 |

- 확인 항목(지표 아님): 집계 함수 단위 테스트 통과, 배포 주소에서 핵심 시나리오(채팅 기록 → 메인 기록 목록 → 채팅 상담) 동작

## 측정 규칙

- **개선 전후 비교**: 과제 평가에서 지표 1개 이상으로 개선 전후를 비교해야 한다. 비교는 같은 시험지 버전끼리만 한다. 시험지가 바뀌면 옛 커밋의 코드로 새 시험지를 다시 풀어 비교한다.
- **측정 기록**: `npm run metrics`가 ID, 날짜, 커밋, 시험지 버전, 값을 `docs/metrics.csv`에 한 줄씩 추가한다.
- **`npm run metrics`는 아직 없다.** R8 표현 사전 테스트와 같은 작업에서 만든다. 만들 때 csv에 적는 ID가 이 표에 있고 폐기되지 않았는지 검사한다.

## ID를 바꾸는 규칙

ID는 고정이다. 문장이나 R 번호가 바뀌어도 ID는 바꾸지 않고, 없앤 ID는 다시 쓰지 않는다.

| 바뀌는 것 | 처리 |
|---|---|
| 문장이나 목표값 | 같은 ID 행을 고치고 `docs/prd/changelog.md`에 한 줄 남긴다 |
| 시험지(케이스 추가·수정) | ID는 그대로, csv의 시험지 버전을 올린다 |
| 재는 대상 자체 | 새 ID를 만들고 옛 행의 상태를 "폐기(→새 ID)"로 둔다. 옛 행은 지우지 않는다 |
